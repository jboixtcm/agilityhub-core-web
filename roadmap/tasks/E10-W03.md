### Assumptions
1. The adopted snapshot is the staged `e1f33710`, not `1110a642`. `1110a642` was superseded in `openapi.next.json` on 17-10 at 19:45, and `e1f33710` contains it.
2. **Handing over the support access.** The contract answers `{token, expiresAt}` with no `launchUrl`, and E47 forbids a JWT in an address. So the console opens the club's back-office host at `/suport` and passes the token by `postMessage`:
   - to the exact origin of the window it opened;
   - only after that window says it is ready;
   - and the receiving tab accepts it only from `window.opener` at the console's origin.
   - Configuration:
     - `VITE_CONSOLE_ORIGIN` defaults to `https://clubsadmin.agilitydoghub.com`.
     - `VITE_CLUB_ADMIN_ORIGINS` maps a host to an origin; only the e2e stacks use it.
   - The host opened is the club's primary VERIFIED `clubs-admin` domain, else another VERIFIED one. With none, the button is disabled and says why.
3. The tenant on the opened host comes from the Host header and must equal the token's `clubId`. That held on the core for the Cànic (`admin.example.test`).
4. «Entra com a administrador del club» lives in «Estat» (S17 §2). The public key has no tab in S17 §2, so it sits at the bottom of «Dominis», as the club website's integration.
5. The club's view of live accesses reads `GET /audit-entries` twice (`action:eq:SUPPORT_ACCESS_STARTED` and `…ENDED`, size 50) and computes the live ones as described above.
