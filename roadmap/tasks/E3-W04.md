2. **ICU plural (review #4).** `signupReview.pending` becomes an ICU plural in ca/es/en:
   - ca: `{count, plural, =0 {pendent des d'avui} one {pendent des de fa # dia} other {pendent des de fa # dies}}`;
   - es: `{count, plural, =0 {pendiente desde hoy} one {pendiente desde hace # día} other {pendiente desde hace # días}}`;

   - S03 R-03-27 fixes one format, and the IBAN never leaves the API beyond the last four digits (GDPR minimisation);
   - the «ES02 ···· 7719» of the D2 mockup is illustrative.

   - Use it in D2, D5 (`CensusListPage`), D10 (`CensusRecordPage`), screen 19 in add-dog mode (`SignupPage`) and screen 28 (`SelfServicePages`).
   - Remove `compactMaskedAccount`.
   - Vitest: T-03-03 (front half), with both input forms the core sends today («···· 1332» and «···· ···· ···· ···· 1332»), plus `null`.

### Assumptions
- **Home of `fmtMaskedIban`:** `packages/i18n`, next to the other `fmt*` helpers. Both apps already depend on it. It strips whitespace and mask characters (`·`, `•`, `*`, `…`) and keeps the last four visible characters. Returns `null` when nothing visible remains.
- **Only an upfront block asks for the amount collected (`manualUpfront`).** Before, a D2 with `billing` on and no upfront (absent or `null`) demanded «Confirma que no s'ha cobrat cap import», but hid its checkbox, so the signup could not be validated. It also sent `upfrontAmountPaid: 0`. Now the amount and the zero-confirmation apply only when `upfront != null` and the upfront was not paid by Stripe.
- **Holder whose `familyGroupId` is null while the claim is `FOUND`:** D2 keeps the E3-W02 behaviour. It shows the generic error and does not validate, instead of validating without the group. «Unless the admin removes the group» has no UI in D2 today, so D2 never sends `familyGroupId: null`.
- **`channel`:** D2 does not render it. D5 reads `paymentMethod?.channel` with `??`, which already treats `null` as absent.
- **Cookie presence in the INC-07 log:** the recorder writes `cookie=sent|none`, meaning whether the browser sent a `Cookie` header on the token request. It never writes the cookie's value. This tells the expected anonymous probe (`400 REFRESH_EXPIRED` with `cookie=none` when a fresh context boots) from a rejected rotation. Token bodies of `2xx` responses are never logged.
- **D10 re-shot:** the seeded member «Laia Fictici006» pays `MANUAL`, so the real D10 shows no account. The masked account on D10 is proven by T-03-39 (MSW) and by the D2 real-core capture.
