# E6-W03 · D12 and D14 — the instructor's week and the follow-up inbox (S10 front, desktop)

## Objective
Work packages S10 WP-10-F and the desktop half of WP-10-E: the instructor reads the whole week at 1280 px (D12) — classes, free-training bookings at half height, ring blocks with their reason —, filters it by instructor and ring, downloads it as a landscape PDF, and passes the attendance of a selected class from the same page with the badge that cycles and `[DESA LA LLISTA]`; and every instructor and administrator has a follow-up inbox (D14) where tasks and student notes arrive with **their own** unread marks and a menu counter. Both screens render `GET /instructor/week` and `GET /followup` as delivered; the save uses the same `PUT /class-sessions/{id}/attendance` contract as screen 21, so the two screens can never disagree. Mocks-first on the S10 schemas of api E6-T01; pixel-faithful to the V7 mockups at 1280 px.

## Fixed conventions
- Design system only (`ScheduleGrid`, `UniversalList`, `Card`, `Badge`, `Toast`); no literal colours; keys never literals; ca/es/en together; vocabulary rules (never «parell*», «amigable», «(paràmetre)» or requirement codes; the red state is «no presentat», never «no assistit» — the old desktop wording is superseded).
- The api decides: the week composition, the ISO week, the cell kinds, `attendanceStatus`, the sheet permissions, the follow-up order and the `unread` flag are rendered as delivered; the front never recomputes a week, an order or an unread condition, and never calls a cancellation endpoint (marking «ha avisat» is what cancels, inside the api transaction).
- The PDF export is **synchronous** (`application/pdf` in the response) — no export job, no polling, no server-side filename assumptions beyond the one the task sets.
- Errors are handled by `code` through `errors:<CODE>`, never by status and never by rendering the api `message` as copy.
- Closed catalogs: no new parameter, event, notification or error code. Proposed literals («Setmana actual» for `relative`, the 409 toast, «avís ja enviat», `shell:nav.weeklyAgenda`) and the `followUpUnread` duplication go to the report and `roadmap/MESSAGES.md` while shipping with the wording above (S10 §13-11).
- Evidence rule: report = command + exit code + last 40 lines; long outputs → `roadmap/evidence/E6-W03/NN-<name>.log`; task file ≤ 120 KB; complete `pnpm e2e` (three projects) in `mcr.microsoft.com/playwright:v1.63.0-noble` before `awaiting_verification`; fictional data only (`@example.test`); no secrets, env vars only; never edit other tasks, `ROADMAP.md` or the Organizer verification section.
