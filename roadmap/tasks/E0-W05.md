# E0-W05 · packages/auth: session, WebCrypto-encrypted refresh token, refresh interceptor, role/module guards

## Objective
The session layer of the front apps, applying decision **A1** of `docs/DECISIONS_PENDENTS.md` (encrypted refresh token in browser storage, access token in memory only).

## Spec references
S01 WP-01-A (client), R-01-06 (refresh rotation) · `docs/decisions/ADR-004` · `docs/DECISIONS_PENDENTS.md` A1 · `docs/specs/00-transversal/MATRIU_PERMISOS.md` (roles) · `docs/specs/00-transversal/CATALEG_MODULS.md` (module → UI).

## Context to load
S01 §6 (`/oauth2/token`, `/me`), A1, MATRIU_PERMISOS, CATALEG_MODULS · this file.

## Steps
1. `AuthClient`: `login(email, password)` (`grant_type=password`), `refresh()` (`grant_type=refresh_token`), `logout()`; access token kept **only in memory**; refresh token encrypted with AES-GCM using a non-extractable `CryptoKey` generated once and stored in IndexedDB (WebCrypto), ciphertext stored in IndexedDB; if WebCrypto/IndexedDB are unavailable → memory-only session and a console warning.
2. Refresh interceptor for the api-client: on `401`, run **a single** `refresh()` (concurrent requests queue behind it) and retry once; if refresh fails → `signedOut` event and redirect to `/acces`.
3. `SessionProvider` + `useSession()` → `{ status: 'loading'|'anonymous'|'signedIn', me, roles, activeProfile }`; components `RequireAuth`, `RequireRole(roles)`, `RequireModule(module)` (reads `useBranding().modules`; a disabled module renders the «No disponible» page and registers no route).
4. Tests with MSW: login → `/me` loaded; 401 → refresh → retried exactly once; ciphertext in IndexedDB does not contain the token (test with `fake-indexeddb` + Node WebCrypto); guards render/redirect correctly.
