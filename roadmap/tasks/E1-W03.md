# E1-W03 · apps/id: login, magic link landing, set password, account page, products page (AgilityHub brand)

## Objective
Work package WP-01-D (front part): the pages of the identity host used by the OIDC `authorize` flow and by accounts without a club context (Learn users).

## Spec references
S01 §2 (`apps/id` routes), R-01-11 (authorize redirects to `/login?…` and back), R-01-14, §14 (Learn accounts, 6 product locales union) · ADR-010, ADR-011 (product locales `ca es en fr de no pt` — the id app serves `ca/es/en` now, others fall back to `en`).

## Context to load
S01 §2, R-01-11, R-01-14 · ADR-010 · `apps/id` shell (E0-W06) · this file.

## Steps
1. `/login` (email → magic link or password; honours `login_hint`, `ui_locales`, and the `authorize` continuation URL), `/magic` (token landing → continue the authorize flow or go to `/account`), `/set-password`, `/account` (name, locale, sessions with revoke, password), `/products` («Els teus productes»: Learn / clubs where the account has memberships, with deep links to each host), `/logout`.
2. AgilityHub brand tokens (not a club theme); no club-specific copy; screens have no mockup — design-system components, literals proposed in the report.
3. OIDC continuation: the backend redirects to `/login?continue=<authorize-url>`; after login the app redirects back so the code is issued to the calling client.
