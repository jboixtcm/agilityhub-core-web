# E5-W03 · Back-office side of E5 (S08/S09 admin reads + S15 WP-15-B fronts)

## Objective
Everything E5 adds to the back-office so the stage's gate can be driven and audited from the browser: the administrator and the instructor see **who** is booked into a class and who is waiting (D4's selected-class card and the screen 23 class drawer, which until now only showed counters), the club reads the ring-usage register (free-training bookings + ring blocks) as a universal list with exports, a member's record shows her class and training bookings, and the S15 processes that E5 turns on (P1 week opening, P2 risk review, P6 waitlist FIFO, P7 payment timeouts, P9 cleanup) become visible and operable: the D11 card «Processos automàtics» with its switch, [Simula] and [Executa ara], and the D1 card «Revisió de classes en risc». Mocks-first on the S08/S09/S15 schemas of api E5-T01.

## Fixed conventions
- Read-only by default: this task adds **no** way for an admin to book or cancel on a member's behalf (that is «Entra com l'abonat», R-08-19) and **no** attendance marking (S10/E6). The only writes are the waitlist removal, the ring-block cancellation, the job switch and the job trigger.
- The api decides: row states, `displayState`, waitlist positions, job cadences, `nextScheduledForLocal`, run effects and the risk statuses. Render `effects.counters` and `WOULD_*` actions as delivered; never label an effect the api did not name.
- Closed catalogs: no new error code, parameter, event or notification. Errors mapped by `code`, handling both the status the spec writes and the one `CATALEG_ERRORS.md` rule 0 implies (`JOB_UNKNOWN` above all).
- Universal lists follow `CONVENCIONS_API.md` §4 through `UniversalList` (saved views, `filter=<field>:<op>:<value>`, `filter-values`, exports drawer) exactly as `CensusListPage` does; never hand-roll a filter.
- Design system only; keys never literals; ca/es/en together; vocabulary rules; every date, hour and cadence in club-local time through `useClubFormats`.
- Literals of the screens without a mockup (the whole D11 card, the ring-usage register, the D10 note, the run drawer) are S15 §2 / S09 §13-8 proposals: list them in the report and in `MESSAGES.md`, and say they are pending Josep's validation in staging.
- Evidence rule: command + exit code + last 40 lines; long outputs → `roadmap/evidence/E5-W03/NN-<name>.log`; task file ≤ 120 KB; complete `pnpm e2e` (three MSW projects) in `mcr.microsoft.com/playwright:v1.63.0-noble` before `awaiting_verification`; fictional data only (`@example.test`); never edit other tasks, `ROADMAP.md` or the Organizer verification section.
