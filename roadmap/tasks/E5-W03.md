### Assumptions
1. **Contract gaps, rendered with what the snapshot has** (no invented fields):
   - `WaitlistEntry` has no member name, so «En espera» lists the dogs («Kira · Lluna»).
   - `ClassBookingItem` has no level, so rows have no level chip.
   - `TrainingBookingListItem` has no end time and no member number, so «Dia i hora» reads «dl 3 · 7:00» and «Abonat» the name only.
   - `BookingListItem` has no description and no ring, so D10's «Classes» table shows day and hour, dog, state and origin.
   - `RingBlockListItem` has no ring name, so the ring comes from `GET /rings`.
2. **Filter values.** The api publishes no `filter-values` for `/training-bookings` or `/ring-blocks`. The universal filter offers the values of the current rows with their counts, read with `fields=<field>` and `size=1000` under the other filters (the api's own list, never hand-made). Counts beyond 1000 rows would be partial.
3. **Ring blocks.** `GET /ring-blocks` has no `from`/`to`/`kind` query parameters in the snapshot; they are `x-filterable`. The tab starts with `from:between:<Monday 00:00>,<next Monday 00:00>` in the club's zone, and a day's filter value is that day's range.
4. **D1 literals.** Form A carries no gender, so the notified names read with the mockup's (and the task's) fixed literals, «avisada {names}» / «avisats {names}». S14/S15 test texts say «avisat Pau + Blat»; the mockup and the task say «avisats». E3-W02's gendered ICU could not be kept.
5. **Job names.** They follow this task's list (e.g. «Obertura de la setmana», «Caducitats»). S15 §10 proposes other ones («Obertura d'inscripcions», «Venciments», …). Both are proposals pending Josep.
6. **Counters.** Every non-zero counter the api sends is shown with a label for the 13 keys S15 names (P1, P2, P3, P4). Any other key reads as sent («key: n»), never an invented label.
7. **Mock catalog.** `GET /jobs` follows the modules: the Cànic (no SINGLE_CLASS) lists 9, `jobsFullClub` (Cànic + SINGLE_CLASS) 10, `jobsMinimalClub` 8. `class-finishing` (every minute) answers `409 JOB_ALREADY_RUNNING` to a manual run. `waitlist-fifo` runs SKIPPED{MODULE_OFF}, because the Cànic's `waitlist.mode` is ALL_AT_ONCE.
8. **Staff-read registrants in the mocks.** Each class's registrants come from its `counters` (booked / waiting) and a rotating fictional pool, so no dog is booked twice at one hour. The census knows the S08/S09 member world's Laura as `member-laura`, and the lists translate that id.
9. **D10 «Veure'ls tots ›».** For classes it loads every booking of the member in the card (page size 1000): no back-office page lists `GET /bookings` yet. For trainings it opens `/entrenaments?vista=reserves&filter=memberId:eq:{id}`.
10. **Impersonation.** The D11 card learns it from the api (`GET /jobs` → `403 IMPERSONATION_DENIED`), because the card is also rendered without a session provider. An admin impersonating inside clubs-admin cannot reach `/parametres` anyway (MEMBER role).
