# E10-W01 · D19 club console

## Objective
Build D19 «Consola de clubs» in `apps/clubs-admin` for the platform role `AGILITYHUB_ADMIN` (ROADMAP E10-W01, size XL), against the E10-T01 contract that E10-T02 implements. Cut #1 applies, as in the API (E10-T02): domains, support access («Entra com a administrador del club») and the public key stay out. List what you leave out in the report.

## Spec references
`docs/specs/S17-consola-de-clubs.md`: the D19 rows of the screens table (list, record tabs, «Nou club» wizard), WP-17-C and T-17-12. The contract is the OpenAPI snapshot in `packages/api-client` (`/platform/clubs…`).

## Context to load
`AGENTS.md` · the universal list pattern (S03) as the other clubs-admin lists use it · the D11 parameters component (S17 reuses it for the `PLATFORM_ONLY` parameters).

## Steps
For each rule, first write the test that fails without it, named after the spec id (`T-17-nn`) where there is one.
1. **Access.** The console lives under `/consola/clubs` and needs `AGILITYHUB_ADMIN`; any other role gets the app's forbidden state. Entry without a club context follows S17 (`apps/id`).
2. **D19 list** (`/consola/clubs`): the universal list with the columns S17 names (name, slug, status, country and time zone, active members, module chips, an admin's last access, SMS of the month, storage, onboarding checklist n/7), the filters the contract publishes (`appliedFilters`), [Nou club], row → record.
3. **D19 record** (`/consola/clubs/:id/{tab}`): the tabs whose operations the contract publishes and cut #1 implements. Identitat; Localització (with the consequences warning); Tema (token editor with a live preview of the `clubs` and `clubs-admin` shells, logo upload through the one upload route, AA contrast validated); Mòduls (toggles with dependencies); Pagaments (Stripe keys write-only, [Prova la connexió]); Legal; Paràmetres (the D11 component, `PLATFORM_ONLY` editable); Catàlegs base; Equip; Ús; Estat (ONBOARDING/ACTIVE/SUSPENDED with a reason). Dominis and the support-access button stay out; Processos and Auditoria only if their platform endpoints are already in the contract.
4. **«Nou club» wizard** (`/consola/clubs/nou`): the 8 steps of S17, the draft kept locally, [CREA EL CLUB] → `POST /platform/clubs` → the record with the onboarding checklist (T-17-12).
5. **i18n and copy.** ca/es/en for every literal. D19 has no mockup: use S17's literals, and list any other copy in the report as proposed literals (AGENTS rule 1).
6. **Errors.** `fieldErrors` shown on their fields (CONVENCIONS_API §6); `STALE_VERSION` and the `409`s handled as the other clubs-admin forms do.

### What was built (by step)
1. **Access.** `/consola/*` is guarded by `RequirePlatformRole platformRole="AGILITYHUB_ADMIN"` (the prop was `role`, which jsx-a11y reads as an ARIA role): any other account gets «Aquest accés és només per a l'equip AgilityHub.» (S17 §2 literal). The menu has a «Plataforma › Consola» group by the account's global role (it was gated by club roles before, so a platform account without a club never saw it). A platform account without a club role lands on `/consola/clubs` after login, after a handoff and on any unknown path; the club exports button is hidden for it. Impersonation never carries the platform role (S01 R-01-16). `apps/id`: the products page shows a «Consola de clubs» card linking to `https://clubsadmin.agilitydoghub.com/consola/clubs`, only for `AGILITYHUB_ADMIN` (S17 §2 «Entrada»). The console is a lazy chunk (`ConsolePage`), never downloaded by club admins.
2. **D19 list** (`ClubsListPage.tsx`): `UniversalList` over `GET /platform/clubs` with S17's columns (name + «plantilla», slug, status badge, country · zone, active members, module chips, last admin access **in each club's own time zone**, SMS of the month, storage, checklist «n/7 · falten: …»), `fields` from the visible columns, sort `name,asc`, the four `x-filterable` filters (`status`, `countryProfile`, `module`, `template`) with chips from the api's `appliedFilters`, the status select, no export (`x-exportable: false`), no saved views (the platform has no `/saved-views`), [Nou club], row → record. The contract has no `filter-values` for this list, so the values are the contract's enums without counts (`UniversalFilterValue.count` is now optional).
3. **D19 record** (`ClubRecordPage.tsx` + `tabs/*`): route-driven tabs `/consola/clubs/:id/{identitat|localitzacio|tema|moduls|pagaments|legal|parametres|catalegs|equip|processos|auditoria|us|estat}`; an `ONBOARDING` club shows its checklist item by item and proposes activation only when complete (R-17-06).
   - Identitat / Localització / Legal: `PATCH` of the changed fields only with the version read; Localització shows the consequences of each change in a modal before saving; `TIMEZONE_CHANGE_BLOCKED` lands on the zone field; Legal's [Publica una versió nova] saves a new `legalTextsVersion` (default: today in the club's zone) with the re-consent notice of §13-4.
   - Tema: 12 colour tokens, typeface, radius, mode, ring palette; AA contrast (4.5:1) on onPrimary/primary, text/background, text/surface blocks the save and `422 THEME_CONTRAST {field}` lands on the colour; logos (logo, dark logo, mark) through `POST /platform/clubs/{id}/theme/upload-url` (one `Idempotency-Key` per file) + signed `PUT`, published as `logoFileKey`/`logoDarkFileKey`/`markFileKey` (`""` removes); live preview of a `clubs` shell and a `clubs-admin` shell with the draft's tokens scoped by `brandingThemeStyle`.
   - Mòduls: 16 switches with what each turns on; a module needing another is disabled until that one is on, and the one it needs cannot go off (CATALEG_MODULS «Depèn de»); presets Complet / Mínim / «Com el club pilot» send `{preset}`; `422 MODULE_DEPENDENCY {module, requires}` names both.
   - Pagaments: SEPA (creditor, suffix, IBAN write-only, its masked form as help), Stripe (publishable key re-entered on each save, secret and webhook secret write-only and kept when blank, «configurada · test · clau pública …xxxx · última prova OK …», [Prova la connexió]), manual instructions per club language; [Retira el proveïdor] with `DELETE ?version=` → `409 PROVIDER_IN_USE {count}` says how many members.
   - Paràmetres: D11's `ParameterControl`/`valueSummary` (now exported, with the target club's languages) over `GET /platform/parameter-catalog`, `PLATFORM` keys editable and badged, `PUT /platform/clubs/{id}/parameters/{key}` (see question 1).
   - Catàlegs base, Equip (invite with key, retire with key, `LAST_ADMIN`, per-account platform role switch with `LAST_PLATFORM_ADMIN`), Processos (`GET /platform/jobs/overview?clubId=` + [Simula] / [Executa ara] with confirmation), Auditoria (`GET /platform/audit-entries?filter=clubId:eq:…`), Ús (month in the club's zone), Estat (ONBOARDING→ACTIVE, ACTIVE→SUSPENDED with a required reason, SUSPENDED→ACTIVE, key per payload).
4. **«Nou club» wizard** (`NewClubWizard.tsx`, `club-definition.ts`): the eight steps of S17 (Identitat with the slug proposed from the name, Localització, Mòduls preset, Pagaments «més tard» or switches without credentials, Tema AgilityHub/club colours with AA check and preview, Catàlegs base from `GET /platform/club-templates`, Primer administrador, Revisió with the club-as-code YAML) → [CREA EL CLUB] → `POST /platform/clubs` (one key, forgotten on any edit) → `/consola/clubs/{id}/identitat?creat=1` with «S'ha creat el club …» and the checklist (T-17-12). A refusal goes back to the step that fixes it (`SLUG_TAKEN` → slug, `fieldErrors` → their field, `MODULE_DEPENDENCY` → Mòduls, `TEMPLATE_CLUB_NOT_FOUND` → Catàlegs). The draft is saved on the device on demand and restored, **without** the admin's email/name and the contact email/phone.
5. **i18n**: new `console` namespace (S17 R-17-13) in ca/es/en; `shell:nav.platform`, three `id:products.*` keys, three missing `admin-audit:actions.*` (`CLUB_CREATED`, `CLUB_PAYMENT_PROVIDER_CHANGED`, `CLUB_ADMIN_INVITED`). `pnpm i18n:check` passes.
6. **Errors**: messages by `code` (never `message`), details-aware for `MODULE_DEPENDENCY`, `PROVIDER_IN_USE`, `CATALOG_NOT_EMPTY`, `FILE_TOO_LARGE`; `fieldErrors` (and single `details.field`) on their fields with `aria-invalid`; `STALE_VERSION` reads the record again and **rebases only the user's own edits** on the fresh values (`useRebasedDraft`), so a fresh version is never sent with stale values; every write disables its form while pending; errors show inside the tab, drawer or modal.

**Cut #1 exclusions (listed as asked):** no «Dominis» tab (no domain table, no DNS instructions, no [Afegeix domini]/[Verifica] — so T-17-12's «pestanya Dominis amb instruccions DNS» part is not done), no domains in the wizard, no «Entra com a administrador del club» (support access, R-17-10), no public API key (R-17-11). Processos and Auditoria are included: their platform endpoints are in the contract.
