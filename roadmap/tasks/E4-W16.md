# E4-W16 · Audit corrections (web)

## Objective
On 26-09 the organizer ran an independent audit of everything verified so far (E0–E4 on the web, three read-only sub-audits; `docs/INCIDENCIES_OBERTES.md` v1.4 and `docs/DECISIONS_PENDENTS.md` v2.0 carry the outcome). ## Steps
1. **«Entra com l'abonat» through the handoff code (INC-15, E17/E47).** `apps/clubs` `/entrar?handoff=<code>` redeems the code with `authClient.exchangeHandoff` (the back office's consumer at `App.tsx:618-643` is the model), enters the impersonated session and shows the banner; D10 opens **only** the `launchUrl` the api returns (a missing `launchUrl` is an error toast, never a same-origin guess) and never writes a token into a URL; the `#impersonation=` fragment path is removed. The mock answers `launchUrl: "<clubs host>/entrar?handoff=<code>"` and redeems it once, like the api. Vitest on both apps; `e2e/core`: admin → D10 → new page → banner «Estàs veient l'app com …» → one member action → the code cannot be redeemed twice.
2. **An impersonated session never refreshes (INC-18).** `acceptImpersonation` (and the handoff of step 1 for an `imp` token) marks the `AuthClient` session as impersonated: no `scheduleRefresh`, no `refreshOnFocus`, no refresh from the 401 interceptor; on 401 the tab ends the impersonation with «La sessió com l'abonat ha caducat» and a close button (never a silent switch to the admin's own member session). Vitest: `window.focus` after `acceptImpersonation` → no `/oauth2/token` call; a 401 → the message, no refresh.
3. **A transient refresh or restore failure keeps the session (INC-19).** In `refreshInBackground`, `performRestoreSession` and the interceptor only a `400`/`401` of the token endpoint ends the session; `ApiError.network` (status 0) and 5xx keep the current token (valid until `expires_in`), retry with backoff and on `online`, and keep the `loading` snapshot instead of `anonymous`. `refreshOnFocus` runs only when `Date.now() ≥ refreshAt − slack`; bind `visibilitychange` and `pageshow` besides `focus` (iOS standalone PWA). `apps/id` gets `navigate: "/login"` (today a failure lands on its 404). `logout()` with a rejected bearer refreshes once and retries the revoke, so the HttpOnly cookie is really revoked. Vitest for each branch.
4. **Production bundles without the mock world (INC-20).** Guard the MSW import with the literal `import.meta.env.VITE_MOCK === "1"` in the three `main.tsx` (so Vite drops the chunk), add `workbox.globIgnores: ["**/browser-*.js", "**/mockServiceWorker.js"]` and `navigateFallbackDenylist: [/^\/api\//, /^\/oauth2\//, /^\/connect\//, /^\/\.well-known\//]` to the PWA config, and extend `.size-limit.json` to `clubs-admin`, `id` and to the total of `dist/assets/*.js` of each app (budget from the measured build minus the mock chunk). Evidence: the three build logs (chunk list, precache size) before and after.
5. **Queued exports can be downloaded (INC-21).** For a READY row the drawer reads `GET /exports/{id}` (the list carries no `downloadUrl` by contract) and downloads an api-relative url through `client.GET(url, { parseAs: "blob" })` + `saveFile` (the E4-W07 proposal), so the bearer travels; an absolute S3 url opens as today. The mock list omits `downloadUrl`, the mock download requires the bearer and the signature. T-14-26 asserts the real path.
6. **«＋ DOC.» after a first upload (INC-22).** `DocumentModal.submit` resets `working` in a `finally`, and `name`/`file`/`chosenType` reset when the dialog opens (or the dialog mounts with `key={upload?.dogId}`). Test: two consecutive uploads on two dogs.
7. **D10 with `BILLING` off keeps its actions (INC-27).** «Bloqueja les reserves»/«Desbloqueja», «Inactivitat», «Baixa (amb data)» and «Tota l'auditoria ›» render whatever the modules; only the invoice rows and «Tots els rebuts» stay behind `BILLING` (S03 R-03-30). Vitest T-03-34 (front).
8. **D8 «Nou preu» tax default.** The default `taxPercent` is the plan's current price's, else `0`; never a country constant in code.
9. **D7 keeps the admin's edits on `STALE_VERSION`.** `failSave` on `STALE_VERSION` calls `refreshVersion()` (rebase) and re-enables [DESA] with the stale notice, as D2's drawer does; the typed rich text survives. Test.
10. **Password recovery (INC-24, ruling E49).** After a `purpose = RESET` link the screen is a reset (title and copy of mockup 02's reset variant), the form has no current-password field and sends `{new, repeat}`; `INVALID_CREDENTIALS` on this path maps to «L'enllaç ja s'ha fet servir: demana'n un altre» with a link to «Recupera-la». The mock enforces `current` like the api (only a RESET session may skip it). Vitest; real-core stage when the E5-T27 image is published.
11. **Task rows on screen 13 (INC-26, R-03-18).** `DogTasks` renders `dog.tasks.items`: pending rows with an inert checkbox (completion arrives with E6-W02) and «{dd-mm} · {instructorName}», done rows struck through with «feta el {dd-mm}», the clip with `attachmentsCount`; the counter stays as the block header. T-03-40 asserts the rows and the strike-through (the real-core capture `roadmap/evidence/E3-W09/13-*.png` shows the seed's tasks).
12. **Three small member-app fixes.** (a) The add-dog «enviada» page titles the header «Afegeix un gos» and offers «TORNA ALS MEUS GOSSOS» → `/gossos`. (b) `activeProfileLabel` («Canviar de perfil · {perfil}») uses the ICU gender select on `me.membership.gender` as 03b does. (c) The onboarding language choice is filtered by `branding.locales`, defaulting to `branding.defaultLocale` when the account locale is not offered.
13. **Docs.** `roadmap/evidence/E4-W16/`: the build logs of step 4, the screenshots of 13 (375 px) and D10 with `BILLING` off (1280 px). No `docs/` edits: the organizer has amended the specs.
