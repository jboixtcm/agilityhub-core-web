## Steps
1. **«Entra com l'abonat» through the handoff code (INC-15, E17/E47).** `apps/clubs` `/entrar?handoff=<code>` redeems the code with `authClient.exchangeHandoff` (the back office's consumer at `App.tsx:618-643` is the model), enters the impersonated session and shows the banner; D10 opens **only** the `launchUrl` the api returns (a missing `launchUrl` is an error toast, never a same-origin guess) and never writes a token into a URL; the `#impersonation=` fragment path is removed. The mock answers `launchUrl: "<clubs host>/entrar?handoff=<code>"` and redeems it once, like the api. Vitest on both apps; `e2e/core`: admin → D10 → new page → banner «Estàs veient l'app com …» → one member action → the code cannot be redeemed twice.
2. **An impersonated session never refreshes (INC-18).** `acceptImpersonation` (and the handoff of step 1 for an `imp` token) marks the `AuthClient` session as impersonated: no `scheduleRefresh`, no `refreshOnFocus`, no refresh from the 401 interceptor; on 401 the tab ends the impersonation with «La sessió com l'abonat ha caducat» and a close button (never a silent switch to the admin's own member session). Vitest: `window.focus` after `acceptImpersonation` → no `/oauth2/token` call; a 401 → the message, no refresh.
3. **A transient refresh or restore failure keeps the session (INC-19).** In `refreshInBackground`, `performRestoreSession` and the interceptor only a `400`/`401` of the token endpoint ends the session; `ApiError.network` (status 0) and 5xx keep the current token (valid until `expires_in`), retry with backoff and on `online`, and keep the `loading` snapshot instead of `anonymous`. `refreshOnFocus` runs only when `Date.now() ≥ refreshAt − slack`; bind `visibilitychange` and `pageshow` besides `focus` (iOS standalone PWA). `apps/id` gets `navigate: "/login"` (today a failure lands on its 404). `logout()` with a rejected bearer refreshes once and retries the revoke, so the HttpOnly cookie is really revoked. Vitest for each branch.

### What changed, step by step
1. **«Entra com l'abonat» (INC-15, E47).**
   - D10 (`CensusRecordPage.tsx`) opens only the api's `launchUrl` (`window.open(launchUrl, "_blank", "noopener,noreferrer")`). A missing `launchUrl` throws inside `run`, so the dialog shows «No s'ha pogut completar l'acció.» and opens nothing. No token is ever written into a URL.
   - `apps/clubs` `AccessPage` redeems `/entrar?handoff=<code>` with `authClient.exchangeHandoff`, modelled on the back office's consumer. It first removes the code from the address (`history.replaceState`), shows «Validant l'enllaç…», then goes to `/inici` for an impersonation, or to `routeAfterLogin` otherwise. A refused code shows «Aquest enllaç ja no és vàlid» on 01.

The handoff grant returns the impersonation token without `refresh_token`, and refuses a second redemption with `400 HANDOFF_INVALID`. Redeemed codes are kept in the origin's storage, so the rule survives the browser mock world's page reloads.
2. **An impersonated session never refreshes (INC-18).**
   - `acceptImpersonation`, and a handoff whose `/me` carries `impersonation`, put `AuthClient` in impersonation mode. The token and its expiry live in **session storage** (`agilityhub.impersonation`), so they survive the app's full-page navigations and die with the tab (assumption A1).
   - In this mode there is no `scheduleRefresh`, no refresh on focus, `visibilitychange` or `pageshow`, and `refresh()` rejects.
   - A 401 goes through the new `recoverFromUnauthorized()`. It ends the impersonation instead of refreshing. The same happens on a restore after the expiry.
   - `SessionProvider` gains the status `impersonationExpired`, and `RequireAuth` never redirects on it. The member app then shows «La sessió com l'abonat ha caducat» with a [Tanca] button (`window.close()`) on every route. The tab keeps that mark, so a reload never falls back to the cookie.
3. **Transient failures keep the session (INC-19).**
   - Only a `400`/`401` of the token endpoint ends a session (`endsSession`). Offline (status 0), a 5xx or anything else keeps the current token.
   - After such a failure, `refreshInBackground`, `performRestoreSession` and the interceptor retry once at a time: after a 2/5/15/30/60 s backoff, or at once on `online`. A failed restore leaves the provider in `loading`, never `anonymous`.
   - A focus, `visibilitychange` (visible) or `pageshow` refreshes only when `Date.now() ≥ refreshAt − 30 s`.
   - `apps/id` passes `signInPath: "/login"`: a dead session no longer lands on its 404.
   - `logout()` with a rejected bearer (`401`) refreshes once and retries the revoke. An impersonation is revoked with its own token, and never refreshed.
