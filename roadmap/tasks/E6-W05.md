## Steps
1. **An upload whose grant expired is uploaded again (E6-W02 review #1, major; R-10-11).**
   - Today an uploaded file's key is kept for good. If the upload succeeds and the task's creation fails, a retry after the grant's five minutes sends the expired key: the api refuses it (`INVALID_STATE` from the claim), and the form cannot recover without picking the files again.
   - Keep a file's key only while its grant lasts, and for the retries of an unanswered submission (E74). After a definitive refusal of the key, or once its grant has expired, upload the file again.
   - Make MSW enforce the grant's expiry. Test: an upload, a failed creation, the clock past five minutes, a retry → the file is uploaded again and the task is created.
2. **A mixed selection keeps its rejection messages (E6-W02 review #2).** When the picker accepts some files and refuses others, the messages of the refused ones stay while the accepted ones upload. Test through `DogFollowupEditor`: a JPEG and an executable → the JPEG is attached and the executable's message stays.
3. **Escape closes only the topmost overlay (E6-W02 review #3; AGENTS rule 6).** Escape in the delete confirmation closes the confirmation only; D13's drawer and its drafts stay. Test: unsaved task text, the delete confirmation, Escape → the drawer is open with the text.
4. **A failed deletion says why inside its dialog (E6-W02 review #4).** Show the translated error inside the confirmation, or close it and move the focus to the visible error. Test a refused delete.
5. **D14's counter when a read and its refresh both fail (E6-W03 review #1, major; R-10-13).** Keep each pending decrement and roll it back locally when its read fails, whatever the counter's refresh does; reconcile with the api when it answers. Test: offline, a read fails and the counter's refresh fails too → the counter is back at its value, and a second failed retry does not lower it.
6. **A successful retry updates D14's row (E6-W03 review #2).** A retried read that succeeds marks the row read in a mounted D14, or makes it read the list again. Test: a failed read, back to D14, a successful retry → the row is no longer highlighted.
7. **es writes day-month dates as «03/08» (E6-W02's question 1).** es uses the zero-padded `dd/MM` of ca and of the mockups, not CLDR's `d/M`. Test the helper and one screen in es.
