### Assumptions
- **A1. The expired claim.** Its answer is `409 INVALID_STATE` with `details: {}`, on `POST /tasks` and `POST /attachments`.
  - The review names `AttachmentService.claim`'s `INVALID_STATE`.
  - The snapshot declares `INVALID_STATE` only on `POST /attachments`, where it is also the frozen dog's `reason: READMISSION_PENDING`; the client never re-uploads for that reason. See Q1.
- **A2. The 30 s margin.** A key within 30 s of its `expiresAt` is uploaded again rather than claimed: the time the claim takes, plus a device clock a little behind the api's. A clock further off is caught by the api's refusal (A3).
- **A3. One automatic retry.** After a refused expired key, the same press uploads again and sends once more; it never loops. The task test shows `409` then `201` and one task.
- **A4. `IN_PROGRESS` handling here.** It lives in the same key helper as step 1, following CONVENCIONS_API §7 (E79). E7-W04 does the same for E7's flows. The UI shows `errors:IDEMPOTENCY_KEY_REUSED` meanwhile; no new literal.
- **A5. Selections.** A new selection replaces the last selection's messages; a cancelled file dialog changes nothing.
- **A5b. An instructor's mixed selection.** An instructor cannot read the limits, so every file goes to the api. The executable is refused at `upload-url` (`FILE_TYPE_NOT_ALLOWED`, no `PUT`), and nothing of that selection is registered: unchanged, every file is uploaded before any is registered. Step 2 covers the picker's refusals (ADMIN).
- **A6. The deletion's error.** It goes inside the confirmation only after that confirmation's own attempt failed; closed, the failure shows in the tasks block.
- **A7. The topmost overlay** is the last open one in document order: nested overlays follow their parent, siblings paint in that order. Menus with their own Escape handlers (D4's, the rich-text link box) are outside `Modal`/`Drawer` and unchanged.
- **A8. D14 after a successful retry.** It briefly shows the list's loading state while it reads again (as read-all does). The api then lists the read row after the unread ones.
- **A9. es dates.** Only `dayMonthNumeric` is padded. es `monthYear` still prints CLDR's «8/2026»; the task did not ask for it, and no screen found here uses it in es. `formatDateRange` is not used anywhere.
