# E2-W08 · Adopt the api E2 contract snapshot — replace the pending.json entries, align fixtures and consumers

## Objective
The api has published and the organizer has verified the E2 contract (api task E2-T01: 104 paths, 223 schemas — members, dogs, family groups, `/me/*`, saved views, exports, levels/rings/instructors/administrators/plans/prices/faq, parameters/club settings, audit entries). The organizer placed that snapshot at **`packages/api-client/openapi/openapi.next.json`** (staged on purpose: the generator's redefinition guard would break `main` if it replaced `openapi.json` while `pending.json` still defines the same paths). Swap it in, delete every now-published entry from `pending.json`, regenerate the types and make every E2 screen and fixture conform to the real contract.

## Fixed conventions
- `mv openapi.next.json openapi.json` (byte for byte; never edit). `pending.json` must end up **empty of anything the snapshot defines** (paths and component schemas); the guard keeps it honest. Anything left in `pending.json` must be listed in the report with the spec row that justifies it.
- Wire names come from the snapshot — e.g. list responses `ListPage*`, `MemberListItem`/`DogListItem` column keys (`fullName`, `dogs`, `plan`, `displayStatus`, … / `name`, `breed`, `level`, `owner`, `freeTraining`, `licenses`, `displayStatus`, …), `x-filter-operators`, `SavedView {listKey, name, columns[], filters[], sort, shared, version}` (no default flag: the default view stays a browser preference), `Member` (`firstName`, `lastName1`, `lastName2`, `contactEmails[]`, `phones[]`, `paymentMethod` masked/write-only IBAN, `consents`, `bookingBlock`, `roles`, `version`), `Dog` (`levelId`, `freeTrainingOverride`, `licenses[]`, `status`, `version`), `MemberInstructorView` for the INSTRUCTOR projection.
- D8 fidelity items from the E2-W04 review: price cell «60 €/mes + entrada 100 €» when the plan has an entry fee, subtitle «(familiar)» under «Abonat · 2 gossos», preview second line «Fins a dues classes per setmana · entrada 100 €» (mockup D8).
- E2-T02 (parameters API) is also in this snapshot: `GET/PUT/DELETE /parameters*` with `default`, `block`, `history`, `PUT /club`, opening hours/holidays (`{date, label}`), `GET /country-profile` — E2-W05 builds on them; here only make the fixtures/handlers you already have conform.
- Spec changes of 06/08/09-09 to absorb here (the api snapshot of E2-T01/T02 does **not** carry the E2-T03…T06 changes yet — `handlerName`, `Plan.billingMode`, licence category/division and the A5 removal of `Level.agilityhubLevel` arrive with later snapshots; for those, keep `pending.json` entries only where the snapshot is silent and align the UI to the spec): **A5** no `agilityhubLevel` on levels (delete the `enums:agilityhubLevel.*` keys and any column/select); **B10** `Plan.billingMode` (`MONTHLY_FEE · MAINTENANCE`) — D10 «Mode de facturació» read-only from the plan, D8 plan form select; **B19** no warning on level change; `Dog.handlerName` (D15 column «Guia», dog record field, `PATCH /dogs/{id}`), `licenses[].category/division`.
- Errors: `STALE_VERSION` (409) on versioned PATCH/PUT, `MEMBER_ERASED` (409, new in the catalog — translation already present), `FAMILY_GROUP_MEMBER_ALREADY_IN_GROUP`, `SAVED_VIEW_NAME_TAKEN`, `EXPORT_LIMIT` (422).
- Every JSON fixture used by MSW for these endpoints is validated by the Ajv contract test against the snapshot schema (extend the mapping); TypeScript fixtures (`census.ts`) must be typed with the generated types.
