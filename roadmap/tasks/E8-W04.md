# E8-W04 · E8 integration (front) — S12 WP-12-F/G/H + S13 WP-13-F, web half

## Objective
The E8 screens (D6, the remittances page, `/rebuts`, 13, 14, 15, the D10 billing block and drawers, `/inactivitats`, D5) run in the browser against the **real published core** with the E8 demo seed of api E8-T06 — Laura with a pending inactivity request, Eva inactive with a frozen fee, Montse with a leave scheduled for 31-08, Joan with an expired 10-session pack and its planned leave, cash members on the half-year branch, and at least one member per payment method. The month's remittance goes simulation → generation → valid XML download → an invoice marked returned → rollback → regeneration with the same numbers; a card charge runs against Stripe test keys when they exist and against `FakePaymentProvider` when they do not; a pack session is consumed by a booking and refunded by an on-time cancellation; an inactivity period and a leave show up as an `INACTIVITY_FEE` line and a missing receipt. The E8 contract is adopted from the real snapshot (no E8 entry left in `pending.json`), and the gate E8 (front) evidence is produced for the organizer.

2. **`e2e/core/e8-core.spec.ts`** (serial, real core, seeded accounts, a fixed test clock where the core exposes one):
   - **(a) Remittance round trip (T-12-27, gate E8 core item).** As ADMIN on `/facturacio?mes=<seed month>`: [1 · SIMULA EL MES] → assert the incident rows, the cash-member rows with their planned leave dates and the KPI numbers **against the seed's own figures** (read them from the `GET /billing/periods/{period}` response, do not hard-code); [2 · GENERA REMESA SEPA (XML)] → the strong confirmation sentence → assert the receipts appear with their `displayNumber` sequence and the chips' counts; go to `/facturacio/remeses`, click [Descarrega l'XML] and assert the download's status, filename and `Content-Type` (**do not parse the XML** — the api's `bin/e8-smoke` validates it against the XSD); back on D6, open a receipt and [Marca impagat] → the row reads «impagat (manual)»; then [Retrocedeix la remesa] → type «RETROCEDIR» → assert every receipt of the run is «anul·lat» and the chips' counts return to zero; simulate and generate again and assert the **same** `displayNumber` values as the first run (R-12-14). Record every step's numbers in the report.
   - **(b) Cash and mark paid.** Mark the seed's cash receipt paid in bulk from the chips («Pendents» → select → [Marcar cobrat (selecció)]) and assert it becomes «cobrat»; assert the cash receipt carries the **half-year** line count the seed produces (A29) and note the number.
   - **(c) Card leg.** On the fictional Stripe club: [COBRA LES TARGETES] → assert the `202` and the run entering `CHARGING`. Also exercise the member side once: `/rebuts` shows the invalid-card banner and [Actualitza la targeta] reaches a `checkoutUrl` (do not complete a real card form).
   - **(d) Pack consumed and refunded.** As the seed member with a live pack: book a class on 04 (E5-W01's flow) → screen 13 shows one session fewer; cancel it within the threshold on 07 → 13 shows it back. Assert against `GET /me/pack-balances`, and assert the expired pack of Joan shows «caducat» with its remaining sessions **not** usable (B11).
   - **(e) Inactivity and leave, end to end (T-13-32).** As Laura: `/inactivitat` → request the seed's next eligible month → as ADMIN: `/inactivitats` «Inactivitats» tab → row → D10 drawer opens → [Aprova] → the toast reports the cancelled bookings → as Laura: screen 04 shows the class of that month as not bookable with the inactivity reason, and the next `/facturacio` simulation shows her line as **«Quota inactivitat — {month}»** (R-13-08).
