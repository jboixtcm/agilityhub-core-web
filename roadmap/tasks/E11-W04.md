# E11-W04 · Spanish actions in the infinitive

## Objective
Make Jordi's rule for Spanish action labels (ruling E137, 21-10) a check that CI runs, apply it to every `es` action label the check finds, and write it into the i18n conventions (size S–M).

## The rule (Jordi, 21-10, ruling E137)
In **Spanish**, a label that names an action the reader triggers — a button, a menu action, a link that acts, a dialog's confirmation, a form's submit, the title of a dialog that names its action, the accessible name of such a control — is written in the **infinitive**, as es-ES software does: «Guardar», «Cancelar», «Reservar», «Enviar», «Volver a intentarlo». **Catalan keeps the imperative of the mockups** («Desa», «Cancel·la», «Torna-ho a provar»); **English is unchanged**. Not touched: nouns and status labels that look like verbs («Reserva confirmada», «Reserva de pista», «Activa» as an adjective), sentences and instructions to the reader («Selecciona el nivel inicial.», «Elige una opción» as a select's placeholder), and calls in the reader's own voice («APÚNTAME», «INSCRÍBEME»).

   - **The script.** Key names are too diverse to select the action keys by name (`booking:waitlist.claim`, `console:theme.preview.book`, `training:confirm.idle`, `notifications:feed.action.CHANGE_CLASS`, `auth:access.enter`), so the script reads **every** `es` string (the flattening of `i18n-check.mjs`) and decides by the string, conservatively:
     - the first word (after a leading «＋», «+» or «·») is in `IMPERATIVES`, a constant list of second-person-singular imperatives with their accents; start from the first words of the 219 — `vuelve, cierra, busca, guarda, anula, abre, elimina, quita, cancela, crea, retira, envía, añade, cambia, publica, edita, muestra, activa, reserva, elige, aprueba, reactiva, selecciona, valida, desactiva, deniega, ordena, rechaza, restaura, duplica, simula, ejecuta, descarta, bloquea, confirma, coge, descarga, copia, limpia, exporta, borra, acepta, entra, recuerda, actualiza, sal, prueba, continúa, paga, invita, modifica` — and add what the catalog shows (Spanish forms only; the script never reads `ca`);
     - the first word is capitalised (an enum value such as `enums:classState.ACTIVE` «activa» is not a label);
     - the string is not a sentence: it does not end in `.`, `…`, `:`, `?` or `!`;
     - the key's last segment does not end in `help`, `description`, `hint`, `required`, `placeholder`, `intro`, `emptyDescription` or `loadError` (instructions and explanations);
     - the key is not in `KEEP`, an explicit map `key → reason` for the nouns, adjectives, titles and instructions the heuristic still catches (expected: `admin-audit:actions.BOOKING_CANCELLED_BY_CLUB` / `…LATE` / `…CREATED_BY_CLUB` «Reserva … por el club» (nouns), `admin-catalogs:common.active`, `admin-catalogs:plans.columns.active`, `admin-courses:doors.active`, `common:gallery.active` «Activa» (adjective), `admin-census:common.choose` «Elige una opción» (a select's placeholder), `admin-courses:import.file` «Elige el archivo…» (a file input's label), `auth:profile.iosInstall`, `auth:profile.pushDenied`, `booking:confirm.swapTitle` (instructions), `id:login.title` «Entra en AgilityHub» (title), `admin-census:signupReview.confirmNothingPaid` (a checkbox statement)). Each `KEEP` entry needs a one-line reason; the list is reported.
     The script prints every flagged string as `<namespace:key> · «<value>»`, the counts (`flagged`, `kept`), and exits 1 when anything is flagged.
