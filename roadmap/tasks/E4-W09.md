## Steps
1. **Time options on slot boundaries (major #1).** Today the options start at the opening minute. With opening hours `07:05–22:00` and `classes.slotMinutes = 10`, every offered time ends in `:05`, `:15`…, and the api refuses them with `INVALID_SLOT_GRANULARITY`.
   - The first option is the opening time rounded **up** to a slot boundary, and the last one ends at or before the closing time.
   - Apply this to every time picker of D4: create, edit and ring block. For ring blocks, follow what the api checks on `from`/`to` (S06 §3).
   - Vitest: an opening at `07:05` with 10-minute slots offers `07:10` first, and a save sends aligned times.
2. **The editor stays locked through conflict recovery (major #2, R-06-09).** After `STALE_VERSION` or `INVALID_STATE`, the card unlocks while the calendar refetch is still pending. An edit made in that window is lost when the refreshed version remounts the card. Success already waits for the new version (`awaitingVersion`); do the same for these two errors, `toggleExempt` included. Vitest with a delayed refetch after a 409: an edit attempted before the refetch lands is refused, and no edit is lost.
3. **Closed days (minor #3, R-02-09).** A weekday missing from `club.openingHours` is closed, not open 7:00–22:00.
   - Represent closed days explicitly, and offer no times on them: a clear message, and submission blocked.
   - Make the mock enforce the same rule: `OUTSIDE_OPENING_HOURS` on a closed day, per the catalog.
   - Vitest with Sunday absent from `club.openingHours`.
