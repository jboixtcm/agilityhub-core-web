# E5-W05 · Follow-ups of E5-W01…E5-W03, and api E5-T29

## Objective
The reviews of E5-W01 (round 2) and E5-W03 found gaps that need data the published contract lacked. Api E5-T29 adds that data and fixes one value (`nextBookableAt`). This task adopts that snapshot and does the web part of each point. It also fixes two E5-W01 details that do not need the api: the mock clock and a literal. The organizer decided them on 27-09 (ruling E67).

**Each fix comes with a test that fails before the fix.**

## Steps
0. **Contract.** Adopt the staged `openapi.next.json` (api E5-T29) byte for byte and run `pnpm api:generate`. Nothing of E5-T29 goes to `pending.json`.
1. **The registrants (E5-W03 review #2).** The state chip reads `displayState` with E5-W01's booking-state literals, never `state`: a past booking reads «feta», and one with a `NO_SHOW` mark «no presentat». The level chip comes from `levelCode`; no chip when it is `null`. Tests on D4's panel and on the instructor's drawer.
2. **«En espera: …» (the D12 mockup literal).** Each name is «{guia} + {gos}», with `handlerName ?? memberFirstName`, and the `position` in FIFO clubs.
3. **The register (E5-W03 assumption 1).** «Dia i hora» reads «{dj 8} · {18:30}–{19:00}» with `endsAtLocal`. «Abonat» reads «{fullName} · {memberNumber}», without « · » when there is no number. The blocks' ring comes from the row's `ringName` and `ringColor`, a deactivated ring's included.
4. **D10's «Classes» table (E5-W03 assumption 1).** Add the description and the ring (dot and name), as E5-W03 step 3 asks.
5. **Complete filter values (E5-W03 review #3).** The universal filter of both tabs of `/entrenaments`, and of D10's bookings, reads `GET /{recurs}/filter-values`, never the rows of one page. Test with a mock of more than 1000 rows, where one value appears only after row 1000.
6. **The NEXT limit note on 29 (E5-W01 round-2 review #1).**
   - Rebuild the NEXT test on a next-week row («dl 10») with the value the api now sends: the coming opening instant.
   - With `limit = 0` the first sentence cannot count classes. Use «Encara no pots reservar classes de la setmana vinent.» (proposed literal; es and en in the locales), followed by B1's second sentence.
7. **The mock clock (E5-W01 round-2 review #2).** The booking world's clock moves after its club's week opening (for example Sunday 2 August at 20:30, with `bookings.weekOpensAt` on Sunday at 20:00). The weeks' labels and `weekKey`s then follow R-08-01 as the api computes them. Move the «done» class so screen 29's `CURRENT` refusal still happens, and refresh the captures that change.
8. **Literals and tests (E5-W01 round-2 review #3, #4 and #6).**
   - `booking:detail.cancelledInTime` no longer names the week: «Anul·lació feta dins el termini establert: pots reservar una altra classe.» (proposed; es and en).
   - The «PAY_TO_BOOK with a swap» test asserts that the note sits above the swap button (`compareDocumentPosition`), or drops «above» from its name.
   - The «90 minutes» test of 07 rewrites `cancellableInTimeUntil` together with `lateCancelThresholdMinutes`, so its warning depends on the 90 minutes.
9. **07's ring dot (E5-W04, question 4).** 07 draws the ring's dot before the title from the `Booking`'s ring colour (api E5-T29 step 9), as mockup 07 does.
10. **`/espera/:id` for a `NOTIFIED` entry (E5-W04, question 5; organizer 27-09).** It reads «plaça alliberada» (`enums:waitlistState.NOTIFIED`, which exists), with [AGAFA LA PLAÇA]. An `ACTIVE` entry keeps «en llista d'espera».
11. **A refreshed grid clears an invalid choice (E5-W02 round-2 review #1).** When 08's grid is read again and the selected slot is no longer free (or its ring is gone), the selection is cleared and [Confirma] is disabled. Test: another member books the slot, focus refreshes the grid.
12. **The offline copy blocks the booking (E5-W02 round-2 review #2).** While a required read shows the offline copy («pot no estar al dia»), [Confirma] stays disabled even if `navigator.onLine` is true, and a retry reads again. Test with a `NETWORK` answer while online.
13. **The detail reaches `DONE` (E5-W02 round-2 review #3).** The detail's clock schedules an update past `endsAt`, so a booking shows `DONE` after its end without a remount. Test with a controlled clock.
14. **`SlotGrid`'s disabled columns (E5-W02 round-2 review #4).** `columns[].disabled` disables that column's cells and their `onCellPress`, in the single-column and the table layouts. Tests for both.

15. **The risk review's mock on any day (E5-W03 round-2 review #1).** The mock's `/risk-review` rows name classes that exist in the calendar world on the day they are read, not only on S15's example day, and a `WILL_CANCEL` never names a class that is already cancelled. Tests on the example day and on another day: each row's class exists in its week, in the state the row implies.
16. **The mock's club scope (E5-W03 round-2 review #2).** The back-office mock finds classes and waitlist entries within the caller's club only. Test: an ADMIN of another club cannot cancel the entry (`404`).
17. **D11 after a schedule change (E5-W03 round-2 review #3).** Saving a `jobs.*` schedule parameter refreshes the jobs card's summaries, so the new cadence shows at once (R-15-01). Test: change `jobs.dailyTime` → the card reads the new time.
18. **The run drawer (E5-W03 round-2 reviews #4 and #5).**
    - A failed history page keeps the pager and offers a retry, and the drawer stays open. Test: page 2 fails once, and the retry shows it.
    - A run's effects link to their entities where the back office has a route for them (R-15-21). A risk-review item opens its class in D4, as D1's rows do. Test.
19. **The E5 core spec (E5-W04 round-2 review, four minors).**
    - (e)'s cancellation asserts that the cancelled booking's own ring (`training.ringId`) is `FREE` in that slot, not «Qualsevol».
    - The cleanup runs in a failure-safe hook (`afterAll`) and still asserts the final states that (h) needs.
    - The Spanish pass repeats (a) and (d): both new bookings on 03, the class gone from 04 after joining, and the waiting entry on 03.
    - The spec imports the generated API types (`Pick` where it needs a few fields) instead of hand-written ones (AGENTS rule 4).
20. **`scripts/e2e-core.sh` cleans up (E5-W04 round-2 question R2-3).** `cleanup` runs `down` with `--profile e2e`, so the Playwright one-off container goes too, and the INT/TERM trap exits after cleaning instead of starting the next stage.
21. **«Ja hi ets» on the core (E4-W16 question 1; api E5-T29 step 10).** With the RESET link's `&purpose=reset`, the real-core stage proves screen 02's «Ja hi ets» and the used-link message.
