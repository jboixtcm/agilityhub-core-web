## Steps
1. **The latest preference wins, whatever fails (E7-W04 review #1; R-11-04), on D10 and on screen 12.**
   - Today the order in which answers arrive stands in for the order in which the PUTs reached the api, and a resend or an older PUT that fails can leave the outbox cleared.
   - When the newest body was sent while an older PUT was pending, resend it once after every older PUT has settled, however it settled (an answer or a network failure). Clear the outbox only on a 2xx for that final send.
   - Test the review's paths a, b and c: the resend fails; the older PUT fails late; the older PUT lands last but answers first. Each time, the latest choice is saved or stays in the outbox.
2. **Screen 12 still saves after a back-forward cache restore (E7-W02 review #1; R-11-04).**
   - Reset the saver's `left` state on `pageshow` with `persisted`, as D10 does (E7-W04, step 4), or make `leave()` depend on what is unsaved.
   - Test: `pagehide` with a change pending → `pageshow` with `persisted` → an edit while a PUT is out → leave → the edit is saved.
3. **A read-all still pending reaches Home after a full-page load (E7-W02 review #2; E7-W02 step 2).**
   - R2-A1 is not accepted: every way back to 03 is a full page load.
   - Keep a «read-all pending» marker in `sessionStorage`, per account and club, until its answer arrives. 03 honours it: it sends read-all again (it is idempotent), then reads `/me/home`.
   - Test with a real page load between the two, and name the test after what it proves.
4. **One text for a write still in progress (E7-W04 question 2; CONVENCIONS_API §7, ruling E80).**
   - `IDEMPOTENCY_KEY_REUSED {reason: IN_PROGRESS}` shows one shared text wherever a write keeps its key: D9's dialog (instead of `admin-messaging:send.inProgress`), the tasks of 26 and D13 (E6-W05), and every other one.
   - Use, for example, `common:inProgress` «L'operació encara està en curs. Torna-ho a provar d'aquí a un moment.», with es and en.
   - `DIFFERENT_REQUEST` keeps `errors:IDEMPOTENCY_KEY_REUSED`.
   - Test two flows.
5. **The tests the review found missing (E7-W04 review #2 and #3).**
   - D10's reconcile on `pageshow` with `persisted`: the keepalive PUT is held across `pagehide`/`pageshow`. The kept patch is sent again as a normal save after it settles, and the outbox clears only after that save is answered.
   - D9's older detail read: a `GET /message-templates/{id}` answer with the older version arrives after a newer save's answer → the newer version stays.
6. **The nits.**
   - E7-W04 #4: an older save answer leaves the detail alone, but still drops the draft it carried (`current[saved.id] === options.savedEdits`).
   - E7-W02 #3: a quiet refetch of 03 that fails keeps the last rows.
   - E7-W02 #4: the preferences outbox entries carry a visit id, so an older visit's success never erases a newer visit's entry.
   - E7-W02 #5: an impersonated session does not show the browser-permission note.
