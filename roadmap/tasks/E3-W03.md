#### Point by point

1. **«Data del proper rebut» — root cause and fix.** The real core returns a PENDING member with no plan reference: `member.plan` = `null` and `member.planId` = `null`, while the proposed plan exists only as `proposals.planId`. The capture is in `roadmap/evidence/E3-W03/d2-signup-view-core.json`. `SignupReviewPage` tested only `signup.member.plan?.type === "MONTHLY"`, so the field never rendered. It now reads `signup.member.plan?.type ?? <type of the proposed plan>`. That type comes from the `/plans` catalog entry (fallback: the `/signup` config plan). The field renders once, in the first dog card, on the same row as «Nivell inicial» (as in the mockup), with the «obligatori» badge.
   - The e2e no longer has an `if visible` branch. `completeValidation(admin, { nextInvoiceDate: { input: "01/10/2026", iso: "2026-10-01" } })` asserts the field and its «obligatori» badge are visible, fills it, and asserts `POST /members/{id}/validation` sends `nextInvoiceDate: "2026-10-01"`.
   - The add-dog validation passes no date, so it is not asserted there.
