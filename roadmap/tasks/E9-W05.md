### Round 2 (17-10-2026, claude:claude-opus-5-5)

**Per point**
1. **A green CI / `TodayPage.test.tsx:304`.** Not the clock: the test asks for `?date=2026-08-04` explicitly and `clubToday` only runs for an invalid date. The failure is a race. DayGrid writes its development log in a `useEffect` (`packages/ui/src/day-grid.tsx:197`). React's scheduler runs the commit and the passive effects in one macrotask, unless the 5 ms slice runs out after the commit. On a loaded CI runner it can run out: the scheduler yields, the commit's DOM mutation resolves `findByRole`, Testing Library's `setTimeout(0)` drain runs, and the assertion runs before the effect. That gives «Number of calls: 0», as in run `38978707008`.
   - **Reproduced** with a temporary setup file loaded before `setup.ts`. It made every `performance.now()` 10 ms later, so the slice is always spent, and delayed `setImmediate` by 20 ms. The unchanged test then failed exactly as in CI (`70-todaypage-loaded-scheduler-before.log`). Delaying `setImmediate` alone does not reproduce it: that first harness passed, in `70-todaypage-slow-scheduler-before.log`, which is misnamed.
   - **Fix:** the assertion now waits for the effect (`await waitFor(() => expect(warn).toHaveBeenCalledWith(…))`). It passes under the same harness (`72`). The harness was then removed (file deleted, `setup.ts` restored). `71` is the whole file under the harness: the fixed test passes, and five fake-timer tests time out because the skewed clock breaks them.
