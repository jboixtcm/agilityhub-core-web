# E1-W06 · Adopt the real api OpenAPI snapshot (S01 contract) — replace the stub, regenerate types, align auth/apps and MSW fixtures

## Objective
E0-W04/E1-W01/E1-W03 were built mocks-first against `packages/api-client/openapi/stub.json`. The api repo has now published the verified S01 contract (`docs/openapi/openapi.json`, task api E1-T01). The organizer copies that file into this repo as `packages/api-client/openapi/openapi.json` when opening this task. Make the generated types come from the real snapshot, delete the stub, and align every consumer and fixture, so that E1-W04 (integration) starts from a contract-exact client.

## Spec references
S01 §6 v0.3 (endpoints, hosts: OAuth2/OIDC on the identity root, everything else under `/api/v1`, including `/auth/magic-link` and `/auth/handoff`), R-01-15 (`Me`: `account.hasPassword`, `emailVerifiedAt?`, `onboardingPending`, `membership.gender?`, `features`) · `docs/specs/00-transversal/CONVENCIONS_API.md`.

## Context to load
`packages/api-client/` (generate script, `openapi/`, `src/mocks/*`) · `packages/auth/src/auth-client.ts` · `apps/clubs/src/App.tsx`, `apps/id/src/*` (consumers of `Me`, branding, tokens) · S01 §6 · this file.

## Fixed conventions
- The snapshot file is the api's, byte for byte: never edit `packages/api-client/openapi/openapi.json` by hand; if the contract is wrong, write it in the report / `MESSAGES.md` for the organizer, who fixes it on the api side.
- Base URLs: `/api/v1/*` paths against the core host (`AuthClientOptions.apiBaseUrl`, today `https://core.agilitydoghub.com/api/v1`), `/oauth2/*`, `/.well-known/*`, `/connect/logout` against the identity host (new option `identityBaseUrl`, default `https://id.agilitydoghub.com`; env names for the apps are yours to define, documented in `docs/playbooks/api-client-usage.md`); the auth client must route by path prefix, not by a single base URL.
- Names come from the snapshot: `Me.features` (not `modules`), `Me.account.hasPassword`, `Me.membership.gender` (`MALE|FEMALE|OTHER`, absent when no member), `OnboardingState`/`OnboardingRequest`, `BrandingResponse.club.city?`.
- MSW fixtures and handlers must validate against the snapshot schemas: add a contract test in `packages/api-client` that loads every fixture in `src/mocks/fixtures/*.json` and validates it against the matching component schema (e.g. with `ajv` + `openapi-types`, or a small custom walker), so future drifts fail in CI.

## Steps
1. Place/confirm `packages/api-client/openapi/openapi.json` (copied by the organizer); point `scripts/generate.mjs` at it; delete `stub.json`; regenerate `src/generated/*`.
2. Fix compile errors across `packages/auth`, `apps/clubs`, `apps/clubs-admin`, `apps/id`: `features`, `hasPassword`, `gender`, magic-link path, `ProfileResponse`, `Session`, `HandoffResponse`, onboarding types.
3. Update fixtures/handlers (`me-*.json`, `branding-*.json`, `sessions.json`, token/magic-link/handoff handlers) to the snapshot shapes; add the fixture-vs-schema contract test.
4. Re-run the E1-W01/E1-W03 unit + e2e suites; refresh screenshots only if something visible changed (it should not).
5. `CHANGELOG.md` entry; note in the report every place where the snapshot forced a behavioural change.
