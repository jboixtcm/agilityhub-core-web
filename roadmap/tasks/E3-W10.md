# E3-W10 · Stable e2e in Docker

## Objective
On the evening of 24-09, `pnpm e2e:docker` failed five runs out of five (E4-W02 round 4 and E4-W04 round 2), always in the same way:
- in clubs-admin, the first 18 of 34 tests timed out, and the dot line was `TTTTTTTTTTTTTTTTTT················`;
- they timed out right after the login: «Bon dia!» or the sidebar link never appeared within 30 s, and one run had «Target crashed»;
- the other 16 tests passed.

The same suite passed at 19:14 in the E3-W06 session. The likely cause is a cold Vite dev server:
- the first two waves of 9 workers hit the servers while the dependency optimisation and the first transforms are still running, on a host that the api lane was also loading;
- when clubs-admin runs after clubs (which also starts the clubs-admin server on 4174), its dependency cache is already warm;
- on 24-09, turbo ran clubs-admin first.

The gate re-run E3-W09 needs this suite green at the first try, and so does every web task's Definition of Done.

This task changes only the e2e infrastructure. Do not change product code or test assertions, and do not add retries or longer test timeouts: the cold start is what must go.

## Context to load
- `apps/clubs-admin/playwright.config.ts`, `apps/clubs/playwright.config.ts` and `apps/id/playwright.config.ts`.
- `scripts/e2e-docker.sh`.
- The failures: `roadmap/evidence/E4-W04/18-e2e-docker-round2-run2.log` and `roadmap/evidence/E4-W02/36-r4-e2e-docker.log`.

## Steps
1. **Warm the dev servers up.** Before the first test starts, each app's run loads every app it serves once in a browser, and waits until that app has rendered:
   - clubs and clubs-admin both start 4173 and 4174;
   - id starts 4175.
   
   Use a Playwright `globalSetup`, or a `setup` project that the tests depend on; either one runs once the `webServer`s answer. The Vite dependency optimisation and the first transforms then happen there, not in the first tests.
   - The warm-up has its own timeout of 180 s.
   - It prints how long each app took.
   - If it fails, the run stops with a clear message.
2. **At most 4 workers under CI.** With `CI=1` (the Docker run sets it), use at most 4 workers per app. Local runs keep Playwright's default.
3. **A lighter copy of the checkout.** `scripts/e2e-docker.sh` tars the whole checkout into the container. On 24-09 that was about 850 MB:
   - about 400 MB was the executor log `.roadmap-executor.log` (the kit now archives it outside the repo once it passes 50 MB);
   - about 390 MB was a stray `.pnpm-store/` from 06-09 that no config uses.
   
   Exclude `.roadmap-*` and `.pnpm-store` from the tar, and print the size of what is copied. Keep the evidence copy-back as it is.
4. **Evidence.** Run the complete `pnpm e2e:docker` twice in a row, through the host lock. For both runs, paste each app's dot line and totals. None may contain a `T`.

## Fixed conventions
- No change to product code, test assertions, retries or test timeouts.
- Heavy runs go through the host lock (step 4a of the task prompt).
- Evidence goes under `roadmap/evidence/E3-W10/`: one log per run, failed runs included.

## Verification (run all; evidence = command + exit code + last 40 lines; long outputs → `roadmap/evidence/E3-W10/*.log`)

- `pnpm e2e:docker`, twice.

## Definition of Done
- Two consecutive complete `pnpm e2e:docker` runs are green, with no timeout.
- The logs show the warm-up times and the copied size.
