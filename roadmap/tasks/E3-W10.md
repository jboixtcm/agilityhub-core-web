# E3-W10 · Test stability

## Objective
On the evening of 24-09, `pnpm e2e:docker` failed five runs out of five (E4-W02 round 4 and E4-W04 round 2), always in the same way:
- in clubs-admin, the first 18 of 34 tests timed out right after the login, and the dot line was `TTTTTTTTTTTTTTTTTT················`;
- runs took 2–5 minutes, and one had «Target crashed».

The E4-W04 round-2 executor found the likely cause:
- E4-W02 round 4 made the mock helper `clubInstant` (`packages/api-client/src/mocks/fixtures/calendar.ts`) sample about 55 offsets per call, each with a new `Intl.DateTimeFormat`;
- every browser page therefore built thousands of formatters when MSW started (the calendar world took 171 ms in Node);
- a per-time-zone cache (`d95b199`) brought it to 38 ms, and the complete suite passed: clubs-admin 34/34 in 22.7 s, clubs 27/27 in 16.6 s.

Two more problems showed up the same evening:
- CI went red at `d95b199` on a flaky Vitest of E4-W01;
- the e2e container copy carried about 790 MB of files it does not need.

This task makes those regressions visible and removes the noise.

**Change no product code.** Test and script changes only.

## Context to load
- `packages/api-client/src/mocks/` (the handlers, the stateful fixtures and their reset).
- `apps/clubs-admin/src/planning/TemplateDayPage.test.tsx` and `TemplateDayPage.tsx` (lines 89–96).

  - `roadmap/evidence/E4-W04/18-e2e-docker-round2-run2.log`;

  - the CI log of `d95b199` (in `.roadmap-ci-fail.log`, or `gh run view 36043032611 --log-failed`).

## Steps
1. **A build-time budget for the mock worlds.** Add a Vitest that builds every stateful mock world, running the same code the browser runs when MSW starts (the handlers' initial fixtures and their reset), and times each one.
   - Measure first, then set the budget at about three times the measured value (for example, 150 ms per world in Node).
   - Show in the report that the test fails with the uncached `clubInstant`: put the pre-`d95b199` helper back temporarily, run the test, and restore it.
   - If E4-W02 is not verified when you run this task, do not touch `apps/clubs-admin/src/planning/calendar-shared.tsx` (it is E4-W02's code).
2. **The flaky D3b test.** `TemplateDayPage.test.tsx`, «rewrites an unknown day in the URL to the template's first day», failed on CI at `d95b199` and passed at `84437c3`. The test asserts `window.location.pathname` right after `findByRole`, before the passive effect that rewrites the URL has run.
   - Keep what the test asserts; only wait for it (`waitFor`).
   - Run the file 20 times in a row, green, and paste the summary.
3. **A lighter copy of the checkout.** `scripts/e2e-docker.sh` tars the whole checkout into the container. On 24-09 that was about 850 MB:
   - about 400 MB was the executor log `.roadmap-executor.log` (the kit now archives it outside the repo once it passes 50 MB);
   - about 390 MB was a stray `.pnpm-store/` from 06-09 that no config uses.
   
   Exclude `.roadmap-*` and `.pnpm-store` from the tar, and print the size of what is copied. Keep the evidence copy-back as it is.
4. **Evidence.** Run the complete `pnpm e2e:docker` twice in a row, through the host lock. For both runs, paste each app's dot line, totals and duration. None may contain a `T`.
