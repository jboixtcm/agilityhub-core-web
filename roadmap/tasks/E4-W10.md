   - Make the mock answer exactly what the core answers (400, `details.field`).
   - Tests: the UI keeps the confirmation open with the error on «Motiu» for the core's payload. The mock test asserts the status and the `details`.
2. **Every registrant in the member filter (review #2, S07 §6).** The member choices of the registrants filter read only the first page: 1,000 rows, with `totalPages` ignored. Vitest: on a closed Sunday, a capacity change keeps [ACCEPTA] disabled, and a notes change saves.
5. **D4 details (E4-W09 review #2–#5).**

   - The card's «Hora» test asserts the PATCH body. The slot tests cite S06 §3 (R-06-11 and T-06-32 for blocks), not R-06-09.
6. **The closed-day rule in D7 and D3 (E4-W09 questions 1 and 2).**

### Assumptions

2. **D7 on a closed day:** [DESA]/[PUBLICA] are not blocked. A draft never blocks rings (S07 §13), and a PATCH of a published activity re-syncs its blocks only when the date, times, rings or place change, so the api decides. The step asked for «a message, and no times». Before a date is typed, D7 still offers the product default window, as it did before; it has no day to check.
3. **D3 while the opening hours are unknown** (loading or failed): the band drawer still saves, and the api validates. `OUTSIDE_OPENING_HOURS` then shows as a general error instead of on a field.
4. The activity mock does not check the opening hours at publication or re-sync. It never did, and the step only asked for the template mock. The api's `details` for that case is not known here.
5. Reading the api repository (`CancellationDeadline.java`) was denied in this session (outside the repository). The `details: {field: "reason"}` shape and the 400 come from the E4-W08 review and this task's step 1.
