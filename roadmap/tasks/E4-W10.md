## Steps
1. **The reason error in the api's real shape (review #1, R-07-09).** For an impersonated cancellation without a reason, the core (`CancellationDeadline.check`) answers `400 VALIDATION_ERROR` with `details: {field: "reason"}`, not `details.fieldErrors[]`. Today the confirmation closes instead of showing the error on «Motiu».
   - Accept both shapes (`details.field` and `details.fieldErrors[]`) in the error helper.
   - Make the mock answer exactly what the core answers (400, `details.field`).
   - Tests: the UI keeps the confirmation open with the error on «Motiu» for the core's payload. The mock test asserts the status and the `details`.
2. **Every registrant in the member filter (review #2, S07 §6).** The member choices of the registrants filter read only the first page: 1,000 rows, with `totalPages` ignored. Read every page, or use a member search. Regression test: with 1,001 distinct members, the member on page 2 can be selected.
3. **Test ids (review #3, AGENTS rule 5).** Add T-07-29 to the D7 suites and T-07-30 to the app suites of E4-W08, and keep their `R-07-*` references.
