## Steps
0. **Adopt the staged snapshot** if `openapi.next.json` is staged (api E3-T14: `MemberSignupView.paymentMethods`), as E3-W07 step 0 did, and prune the matching `pending.json` entries.
   - `scripts/e2e-core.sh` stages E3 on a fresh seed only for `E3-W03`…`E3-W09` (`^E3-W0[3-9]$`), so `pnpm e2e:core E3-W11` would run without the E3 stage. Stage E3 on a fresh seed for **every** task id (E4-W05 step 7 asked for this; it is brought forward here).
1. **A reload drops the quote at once (review #1, §2 D2, R-04-15).** When a reload starts (after `STALE_VERSION`, or when the admin asks for it), the current quote is dropped and [VALIDA] is disabled. It stays disabled until the reload **and** a new quote have both succeeded. A failed reload shows its error in the page, with [Torna-ho a provar]; the old quote is never shown again. Vitest:
   - a delayed reload after `STALE_VERSION`: no upfront block and [VALIDA] disabled while it is pending;
   - a failed reload: the error with a retry, and still no stale quote.
2. **The payment methods come from the D2 view (review #2, R-04-10, R-04-19).** The drawer's selector offers the view's `paymentMethods` (api E3-T14), not every provider key of `/club`. Only the `assignable` methods can be chosen, and `current` is preselected. When none is assignable (an add-dog: the member is not `PENDING`, and R-04-19 sends the method to D10), show the current method read-only. An empty list (an `ACTIVE` member without a method) shows no method row. Vitest: a view where `CARD` is not assignable offers no «Targeta», and still shows the applicant's own method; an add-dog view shows the method read-only. Check the real core in `pnpm e2e:core E3-W11`.
