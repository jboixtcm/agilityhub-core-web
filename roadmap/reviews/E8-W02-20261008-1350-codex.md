# Review E8-W02 — needs changes

## Findings

1. **major** `apps/clubs/src/App.tsx:1695` — Checkout confirmation never refreshes the booking detail. `CheckoutReturn` receives no `onPaid`, while `useBooking` reads only on mount or explicit refetch. Reproduced: checkout reaches `PAID`, but the detail remains `PAYMENT_PENDING`, with cancellation unavailable. The browser test uses an already confirmed booking and misses this transition. Connect payment confirmation to an authoritative booking refetch and test pending → confirmed (Step 4; S12 R-12-21).

2. **minor** `apps/clubs/src/inactivity/InactivityPage.tsx:403` — Submission is enabled while the booking preview is debouncing or awaiting its response. The guard blocks only an already failed preview or an explicit retry. Reproduced a successful POST before any preview request started; changing months creates the same gap. A member can therefore submit without seeing the applicable cancellation warning. Require a successful preview for the current range before submission and test delayed responses (Step 6; R-13-06).

3. **minor** `apps/clubs/src/inactivity/InactivityPage.tsx:343` — Consultation mode always displays `context.fee`, ignoring the selected period’s `fee`. When configuration changes after approval, this displays the current tariff instead of that period’s frozen amounts. Render the period-specific fee for an existing approved/active period, retaining the context fee for new requests; test differing amounts (R-13-08).

4. **minor** `apps/clubs-admin/src/census/MemberBillingBlock.tsx:189` — A successful pack adjustment refreshes only this component. D10’s existing dog row still renders `overview.dogs[].pack` in `CensusRecordPage.tsx:774`, and the billing block has no callback to refresh that overview. Adjusting four remaining sessions to six leaves two contradictory balances on the same page until reload. Refresh or reconcile the parent overview after the write and test both displays together (Step 8; R-12-24).

5. **minor** `packages/api-client/src/mocks/member-billing-handlers.ts:109` — Lifecycle persistence introduces an unrequested inactivity period in `memberNoInactivity`. The scenario hides the seeded period when reading, but a leave-only POST persists that hidden seed; restoration then sets `memberCreatedInactivity = true` from its nonempty array. Reproduced: inactivity periods change from `[]` to the seeded `REQUESTED` “Descans de la Duna” after submitting only a leave request. Persist the scenario’s effective collection or preserve the creation flag, and add a leave-only reload regression (Step 10; Round 4 point 6).

6. **minor** `apps/clubs/src/SelfServicePages.tsx:857` — Failed pack-balance reads are silently converted to `[]`. A network/server failure makes every pack disappear, indistinguishable from having no balance, with no error or retry action. Preserve existing balances during refresh and expose a local loading/error/retry state; keep module-off handling separate (Step 5’s real pack balance requirement).
