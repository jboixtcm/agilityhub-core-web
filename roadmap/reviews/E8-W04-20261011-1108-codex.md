# Review E8-W04 — needs changes

## Findings

1. **major** `apps/clubs-admin/src/billing/BillingPage.tsx:300` — Settlement can create a continuous refresh loop. While the cached period still says `CHARGING`, every `COMPLETED` run-detail response calls `refreshAll()`. Since the detail effect also depends on `reload`, a fast detail response restarts both reads and invalidates the slower period response repeatedly. D6 can remain “charging” while issuing requests outside the five-second polling interval. This undermines step 6b(a). Trigger settlement refresh once per transition and add a regression test where the period response is slower than the completed detail response.

2. **major** `apps/clubs-admin/src/audit/ExportsDrawer.tsx:110` — Queued accounting exports disappear when the drawer is reopened. The initial `202` opens `ACCOUNTING`, but closing it and using the header’s `openExports()` resets the filter to `LIST`. Reloading has the same outcome; there is no kind selector to recover the accounting job. The `EXPORT_LIMIT` handler also loses the accounting kind. Step 3’s asynchronous export flow remains incomplete. Make existing accounting jobs discoverable from the normal exports entry point, preserve the kind on errors, and test closing/reopening while a job finishes.

3. **minor** `e2e/core/e8-core.spec.ts:1524` — Generated inactivity-fee verification is conditional on finding the expected fee in the simulation. If that fee disappears unexpectedly, the test skips receipt assertions and both `/rebuts` and D10 captures and still passes. No seed-range assertion enforces the report’s claim that this proof remains mandatory on normal runs. Step 2(e), R-13-08 and the Definition of Done require the receipt effect. Assert the expected fee from independently established lifecycle dates, and arrange a billable inactive member for moved-date runs instead of silently dropping the check.

4. **minor** `packages/api-client/openapi/pending.json:9` — Step 0 remains partial: `SavedView.system` and `DashboardCounters.pendingInactivityRequests/pendingLeaveRequests` remain as E8 overlays. The report acknowledges this, but an empty `paths` object does not satisfy the requirement to remove every E8 path **and schema**. Obtain an explicit organizer exception for these unresolved contract fields, or publish/adopt them and remove the overlays before treating contract adoption as complete.
