# Review E10-W03 — needs changes

## Findings

1. **major** `apps/clubs-admin/src/support/SupportPages.tsx:151` — “Surt” displays the completed-exit page before revocation finishes and silently discards any rejection. On a network failure or 5xx, the grant can remain valid while the UI says the user can close the tab; `AuthClient.logout()` also clears the token needed to retry. This leaves Step 2 / R-17-10’s revocation incomplete. Keep the early shell exit, but show a pending state until revocation succeeds, expose failures, and preserve a safe retry path. Add delayed-response and failed-revocation tests.

2. **major** `e2e/core/e10-core.spec.ts:314` — The required successful domain-verification flow passes when the core returns `422 HOST_NOT_VERIFIED`. The committed evidence records exactly that response, so a core that never verifies domains still passes this test. E10-W03 Verification and S17 T-17-03 require verification using fake DNS. Configure a deterministic positive DNS fixture and assert `200`, `VERIFIED`, primary selection, and the expected host acceptance; retain the 422 scenario as a separate test.

3. **minor** `apps/clubs-admin/src/console/tabs/ParametersTab.tsx:229` — Reread errors are displayed only when no cached data exists. After `STALE_VERSION` followed by a failed GET, the editor retains the old value/version, presents it as the current value, and permits another stale submission. A successful save followed by a failed GET likewise leaves obsolete rows without warning. This undermines organizer point #4’s fresh-version behavior. Surface reread failures, provide retry, and disable saving until the reread succeeds while preserving the draft.

4. **minor** `apps/clubs-admin/src/audit/SupportAccessesCard.tsx:66` — Live-access discovery reads only page zero of both audit queries and ignores pagination metadata. With 51 live grants, the oldest is omitted and has no “Acaba l’accés” control, contrary to R-17-10 / E123. An in-memory check reproduced 50 displayed grants from 51 available. Traverse all relevant pages and add a pagination regression test.

5. **minor** `apps/clubs-admin/src/console/tabs/ParametersTab.tsx:207` — Newly exposed platform parameters lack translated labels/help and the `system` block lacks a translated title in all three locales. The committed screenshot displays `system` and `auth.sessionDays` directly. The translation checker excludes these parameters because D11 previously hid them. This leaves S17 R-17-13 and AGENTS rule 1 incomplete. Add ca/es/en strings for the platform parameters now rendered by D19 and extend coverage accordingly.
