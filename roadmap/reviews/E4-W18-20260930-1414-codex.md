# Review E4-W18 — needs changes

## Findings

1. **major** `packages/auth/src/auth-client.ts:1011` — The no-cookie marker is written only after the token request settles. `AccessPage` removes `?handoff=` before starting that request, so reloading during a slow/offline exchange loses the handoff state and restores the admin’s cookie session without an impersonation banner. I reproduced grants `["urn:agilityhub:grant:handoff", "refresh_token"]` and an authenticated, non-impersonated session after the simulated reload. This leaves step 1’s “once tried” guarantee and E47 incomplete. Persist the no-cookie state before awaiting `/oauth2/token`, transition it on success, and test reloading while the request remains unresolved.

2. **minor** `apps/clubs-admin/src/App.tsx:704` — Background recovery can emit `signedIn` before this effect attaches its listener. I reproduced three transient `/me` failures followed by successful cookie restoration: `getMe()` was populated, but navigation never occurred and the retry card remained visible. This preserves the stuck-screen case step 2 is intended to fix. After subscribing, immediately check the current session, or drive navigation from reactive session state. Add a test where recovery succeeds without clicking Retry.

3. **minor** `roadmap/tasks/E4-W18.md:302` — Step 3 lacks the failing-before evidence required by the Definition of Done, despite the report’s opening claim that every fix has that proof. The successful current-image run does not demonstrate failure when `launchUrl` disappears or the first password PUT returns 401. An older image is unnecessary: intercept those responses in separate negative runs and record that the revised checks fail, or obtain an explicit organizer exception.
