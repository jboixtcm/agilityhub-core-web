2. **major** `apps/clubs-admin/src/planning/TemplatesPage.tsx:1015-1026` and `ClassForm.tsx:192-201`: edit mode can send PATCHes with an old `version`. Each chip click fires `PATCH …/classes/{classId}` with `version: current.version` taken from the last render. A second click before the first response returns (for example toggling levels E then F) sends the old version again. The real API (and the mock, `planning-handlers.ts:492`) answers 409 `STALE_VERSION`. `ClassForm` has already updated `values` locally and never rolls back or reloads. The chip stays selected but the change is not saved. It also shows as a generic error, even though R-06-02 says "each change is saved at once". The test "saves every change of a full cell at once" waits between the two clicks, so it cannot catch this. **Fix:** one of:
   - queue the PATCHes, or disable the card while one is running;
   - read the version from a ref that `applyTemplate` updates.

   Also, on `STALE_VERSION`: reload the template and remount the card.
