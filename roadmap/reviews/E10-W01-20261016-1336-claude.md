## Findings
1. **minor** `packages/ui/src/tokens.css:100-131` — The product preset (`--ah-product-light-*` / `--ah-product-dark-*`) is a second, hand-copied set of hex values.
   - **What's wrong:** the light values are the `color-mix` results of the default `--ah-color-*` tokens, computed by hand. The dark values copy the `prefers-color-scheme` block (and `success`/`warning`/`danger`/`info` from `:root`). No test ties the two together. `product-theme.test.ts` only checks the format, that the AA checks pass and that light ≠ dark.
   - **Why it matters:** if someone changes the default tokens, the product's own UI moves but new clubs still get the old colours. That is the same kind of theme drift that round-2 point #2 was about.
   - **Suggested fix:** add a test that parses `tokens.css?raw` and asserts each `--ah-product-light-<x>` equals the matching default `--ah-color-*` token (with `color-mix` resolved), and that the dark ones equal the dark block. Alternatively, define the defaults from the product tokens.

2. **minor** `apps/clubs-admin/src/console/ClubRecordPage.tsx:190-203` — After a failed reread, the new alert says «Torna-ho a provar abans de fer cap altre canvi», but every tab form stays enabled.
   - **Why it matters:** a write sent with the possibly stale `version` gets a `409 STALE_VERSION`. That then triggers another reread, which may fail the same way. The user is warned but not protected.
   - **Suggested fix (either):**
     - disable the tab's submit buttons while `record.error !== undefined`; or
     - accept the warning as the mitigation and drop «abans de fer cap altre canvi» from the copy (ca/es/en).

3. **nit** `apps/clubs-admin/src/console/ConsolePage.tsx:15` — The old `/consola/clubs/:id/parametres` URL shows Identitat (and the test asserts that), but the address bar keeps `/parametres`.
   - **Why it matters:** this is the same address / lit-tab mismatch that round-2 point #6 fixed at app level for unknown paths.
   - **Suggested fix:** `replaceState` to `/identitat` when the segment is not a known tab.

4. **nit** `apps/clubs-admin/src/console/tabs/ThemeTab.tsx:519-546` — The `FormField` label and help text («logoPending: …») are still attached to the hidden file input; the visible button only has its own `aria-label`.
   - **Why it matters:** a screen-reader user on «Tria una imatge: Logo» doesn't hear the pending-file help. Upload errors are fine: they are `role="alert"`.
   - **Suggested fix:** give the button `aria-describedby` pointing at the help text.

5. **nit** `scripts/i18n-check.mjs:196-200` — The four SEPA keys are still matched with `startsWith`, so a future key like `console:payments.sepa.creditorIdHelp` would silently count as used. No such key exists today.
   - **Suggested fix:** use exact keys (a `Set`) for these four instead of prefixes.

6. **nit** (report) — `auto` mode sends the light palette. This is recorded as a round-2 assumption, but it is not in the question list for E10-T04, next to the `theme.preset` question. The organizer should decide whether it needs a ruling.
