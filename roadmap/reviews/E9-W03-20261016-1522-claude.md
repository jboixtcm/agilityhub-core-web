# Review E9-W03 (round 2) — minor issues

All 14 points of ruling E119 are implemented. I found no blocker and no major. The four round-1 majors are fixed, and each fix has a test that would fail without it:
- **PUT keeps what the user did not edit:** the PUT body is now the stored placement plus the user's edits, and the R-16-06 test checks that grades, sizes, schedule, threshold, status, mode and name survive a re-save.
- **A course changed meanwhile:** after `STALE_VERSION` the editor re-reads the course and saves at the new course version.
- **No dead «Registra-ho com a muntat» for an INSTRUCTOR:** the action is hidden when the parameter reads `false`, or after the api's first `403`. This matches the way `activities/shared.tsx` treats a `403` on `/parameters`.
- **Tests that can fail:** the alert and accessible-description assertions are now real.

## Findings
1. **minor** `apps/clubs-admin/src/courses/CourseDetailPage.tsx:519-528`, `PlacementEditorPage.tsx:565-582`, `activities/ActivityPlacementsCard.tsx:181-193`: «Full desat» (the stored build sheet) is still offered on a stale placement.
   - Point 6 disables only the button that generates a new sheet. The stored PDF was made from obstacles and marker distances on the old geometry, which is exactly the case R-16-06 / review #7 wanted blocked.
   - The same can happen after a placement is moved and re-saved: the stored sheet then shows the old position. The contract does not say whether `PUT` clears `buildSheetFileKey`.
   - **Fix:** disable the stored-sheet button too (or warn) while `placement.stale`. Ask the api whether `PUT /placements/{id}` should clear `buildSheetFileKey`.
2. **minor** `packages/api-client/src/mocks/course-handlers.ts:137-162` (`keyed()`): the stored answer is keyed only by method + path + `Idempotency-Key`, not by caller.
   - With the new `coursesOtherClub` scenario, the same account in another club reusing a key on `POST /courses`, `dismantle` or `renewal` gets this club's stored 200 back, with this club's course or setup in it. That breaks the club isolation R-16-16 / T-16-05 asks for, and CONVENCIONS_API §7 / E62 says it must answer `409 IDEMPOTENCY_KEY_REUSED`.
   - The executor raised this as round-2 question 2 and left it. E9-W04 builds on these mocks.
   - **Fix:** add club, account and roles to the stored key, plus a T-16-05 case.
3. **minor** `course-handlers.ts`: the mocks are looser than the contract in three places.
   - `placementProblem` (`:409-413`) does not check that `activityId` belongs to the club (openapi `POST`/`PUT /placements`).
   - `GET /placements` (`:941-965`) answers `[]` instead of `NOT_FOUND` for another club's `ringId`/`activityId`.
   - `POST /placements/{id}/build-sheet` (`:1029-1031`) binds a key that was granted but never uploaded: it answers 200, then `GET` answers 404 (T-16-19 says the POST «desa el PDF»).
4. **minor** `course-handlers.test.ts` (T-16-05): three cross-club cases pass even without the check they are meant to test.
   - `:254`: `DELETE /rings/ring-carretera/geometry` is a ring with no geometry, so it answers 404 anyway. The `ring-central` case on `:255` does catch the bug.
   - `:262-264`: the build-sheet POST with `fileKey: "x"` is an unknown key, so 404 anyway. Use a real `BUILD_SHEET` key uploaded by `coursesOtherClub`.
   - `:241`: `GET /obstacle-inventories/ring:ring-muntanya` returns 404 only because the other club has no club inventory yet. Repeat it after that club's `PUT /obstacle-inventories/club`.
5. **minor** `packages/i18n/src/resources.ts:11-12`, `clubs-resources.test.ts:26`: keeping admin namespaces out of `clubs` depends on tree-shaking.
   - About 30 clubs files import the root `@agilityhub/i18n`, which re-exports `./resources` and `./setup`. The comment «apps/clubs never imports this module» is therefore wrong.
   - The only guard is size-limit (288/420 kB): one or two leaked admin namespaces would pass it.
   - `i18n-namespaces.test.ts` scans only `apps/clubs/src`, and only static `t("ns:` / `useTranslation` forms.
   - **Fix:** a check that the built `apps/clubs/dist/assets` contains no `admin-*`, `console` or `id` chunk, or a root entry without `resources`/`setup`.
6. **minor** `packages/course-ui/src/components/PlannerCanvas.tsx:301-342`: drags still lack pointer capture.
   - There is no `setPointerCapture` and no `lostpointercapture` handler. If a non-mouse `pointerup` is missed, `drag.current` keeps a dead `pointerId`, and every later drag is ignored until reload.
   - After a mouse release outside the svg, hovering back moves the course with no button pressed (`event.buttons` is never checked; this predates the round).
7. **nit** `SelectedClassCard.tsx:445-450`: the `role="alert"` error sits inside the `<label>` that wraps the select. The error text may then also become part of the select's accessible name, on top of `aria-describedby`. Put the error after the label.
8. **nit** `RegisterSetupModal.tsx:139-141`: every `FORBIDDEN` reads «En aquest club només l'administració pot registrar…». That includes an ADMIN refused for another reason (for example impersonation, where the api answers `IMPERSONATION_DENIED`/`FORBIDDEN`). Use the instructor text only when the reader is not an ADMIN.
9. **nit** `shared.tsx` `setupRefusals`: the refusal is kept in a module-level `Set` for the whole tab. If the admin turns `courses.allowInstructorPublish` back on, the instructor must reload the page to see the action again. This is acceptable, but it should be written down as an assumption.
10. **nit** `admin-courses.json` `geometry.markerSheetTooLarge` / `markerSheet.size`: `{mm}` is a plain ICU argument, so a decimal value prints «150.5 mm» in `ca`/`es`. Use `{mm, number}` (CONVENCIONS_I18N formats).
11. **nit** `packages/course-ui/tests/sheets.test.tsx`:
    - The UTF-16BE title test has no character outside the BMP (no surrogate pair).
    - The `pointercancel` test fires `click` with no `pointerdown` first, so it is more synthetic than the real bug.
