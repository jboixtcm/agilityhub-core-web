# Review E3-W07 — needs changes

## Findings

1. **major** `apps/clubs-admin/src/dashboard/SignupReviewPage.tsx:219` — Switching language silently changes a manually entered invoice date. `dateInput` retains the localized text, which is reparsed using the new locale on every render. An isolated probe confirmed that entering `10/11/2026` in Catalan sends `2026-11-10`, but switching to English sends `2026-10-11` without editing the date. This can schedule billing for the wrong month (S04 §10, R-04-15). Store the selected date canonically and reformat its display when the locale changes; add a regression test.

2. **major** `apps/clubs-admin/src/dashboard/SignupReviewPage.tsx:274` — Quotes are not invalidated when a plan change fails or the signup reloads. After successfully quoting Pack 6, a failed Pack 10 quote leaves Pack 10 selected, the previous €135 breakdown/max visible, and VALIDA enabled. Reloading also retains `quote`, which overrides fresh payment information at line 221; a probe confirmed that a newly fully paid signup still showed an editable amount. This breaks steps 4/8 and S04 §2. Associate quotes with the selected plan/price and signup version, invalidate obsolete requests/results, and prevent validation until the applicable quote succeeds.

3. **minor** `apps/clubs-admin/src/dashboard/SignupEditDrawer.tsx:532` — The full edit drawer still cannot change the payment method. It only exposes SEPA details when the applicant already selected `SEPA_DD`; a pending MANUAL applicant cannot be corrected to direct debit. S04 §2 and R-04-19 require editing the payment fields from screen 19. Add a selector using the club’s available methods, serialize the corresponding patch, and test a method change while preserving the add-dog restrictions.

4. **minor** `packages/api-client/src/mocks/fixtures/signup-review.ts:212` — The new mock implements the superseded partial-payment behavior rather than E39b. It retains a PARTIAL line’s entire original amount when summing the new balance. Running the actual helper with €50 paid against €100 and a new €60 quote produced €60 outstanding instead of €10. Consequently, the mock cannot validate the intended financial behavior. Model the cancelled original plus a PAID correction for the collected amount, and assert the E39b example in the tests.

5. **minor** `roadmap/tasks/E3-W07.md:167` — The claim that step 8 is complete exceeds the supplied implementation/evidence. The first-month metadata exists only in `pending.json`; the report itself acknowledges that the real core still renders “Primera quota” without the month or portion. Publish/adopt the required API field and verify the rendering, or explicitly record this requirement as deferred rather than completed.
