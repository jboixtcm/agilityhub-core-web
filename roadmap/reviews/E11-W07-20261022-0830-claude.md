# Review E11-W07 — minor issues

## Findings
1. **minor** `apps/clubs-admin/src/billing/BillingPage.tsx:1063-1079`: the «Presenta-la al banc abans del {requestedCollectionDate}» notice shows whenever the remittance is `GENERATED`. That includes the collection date itself and every day after it.
   - Screenshot `63-D6-collection-date-passed-1280.png` (01/09) shows «Presenta-la al banc abans del 01/09» in the warning tone on 01/09. Next to it, the disabled rollback says «Ja ha passat la data de cobrament».
   - Why it matters: R-12-15 / E147 say D6 warns «marca la remesa com a enviada». It should never ask the admin to submit "before" a date that has already arrived.
   - Fix: hide the notice (or switch to a past-date text) when `run.rollbackBlockers ∋ COLLECTION_DATE_PASSED`. Better still, word the warning state after R-12-15 ("mark it as sent"). Add a test for the 01/09 state of the KPI.
2. **minor** `apps/clubs-admin/src/census/MemberBillingBlock.tsx:304-327` together with `CensusRecordPage.tsx:751`: D10 now shows «Proper rebut» twice, as screenshot `60-D10-next-invoice-1280.png` shows.
   - The data card row comes from the mockup (`D10-fitxa-d-abonat.html:220`) and reads `overview.nextInvoice.date`.
   - The new billing-block section reads `member.nextInvoiceDate`, so the two can disagree. Its «Edita» also looks different from the data card's small «Edita» chips.
   - Step 2 did ask for the date in `MemberBillingBlock`. But AGENTS rule 1 (mockup fidelity) points to putting the edit action and the «Sense data: no es facturarà» state on the mockup's existing row instead.
   - Fix: either move it to the existing row, or have the organizer confirm the duplicate.
3. **minor** `BillingPage.tsx:923`: the disabled rollback with the «data de cobrament» reason appears whenever `rollbackBlockers` includes `COLLECTION_DATE_PASSED`, even when other blockers are present too (`INVOICE_PAID`, `MANUAL_INVOICE_AFTER`, `REMITTANCE_SUBMITTED`).
   - Why it matters: per R-12-14 / E156, `FITXER_NO_ENVIAT` lifts only `COLLECTION_DATE_PASSED`. So the stated reason and its advice ("mark it as sent or wait") would be wrong or incomplete in that case, and E11-W08 would build on this branch.
   - Fix: show it only when that is the only blocker, or list every blocker's enum label (`enums:rollbackBlocker.*` already exists).
4. **minor** `MemberBillingBlock.tsx:96` / `CensusRecordPage.tsx:879`: `?calaix=proper-rebut` opens the date drawer whatever the member's plan.
   - For a pack member without a date, the section is hidden (`shownNext == null && !monthly`), yet the drawer still opens and can PUT a date.
   - The query parameter is also never removed, so a reload reopens the drawer.
   - Fix: make `nextOpen`'s initial value depend on `monthly || nextInvoiceDate != null`, and clear the parameter on close.
5. **minor** `packages/api-client/src/mocks/member-billing-handlers.ts:851`: on a change to MONTHLY without a date, the plan-change mock always sets next month's **1st**. The UI (`MemberPlanDrawer`) instead promises next month's `billing.nextInvoiceDayOfMonth`, which the contract also states.
   - With a club override (as in the test that uses 5), the mock and the sentence disagree.
   - Fix: read the parameter in the mock (`findParameter` is already imported).
6. **minor (evidence)** The report admits that `11-lint-typecheck.log`, `12-test-build.log` and `13-size.log` were overwritten by the passing re-runs.
   - So the earlier failures are described but not kept, which goes against AGENTS session protocol §4 ("earlier failing attempts … plus their log file"). `13a-size-over-budget.log` only keeps a tail.
   - Not blocking, but those first-attempt failures cannot be audited.
7. **minor (scope / budget)** `.size-limit.json`: the executor raised «clubs-admin all JavaScript» from 670 to 675 kB on its own, to absorb +2.38 kB. This is flagged in Q2, but it needs the organizer's explicit acceptance; otherwise a lazy D6/D10 split should be planned.
