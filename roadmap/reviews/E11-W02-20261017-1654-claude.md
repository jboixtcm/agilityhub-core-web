# Review E11-W02: needs changes

## Findings
1. **major** `apps/clubs/src/states.test.tsx:108-117`: the 17 "loading" checks in the members' app no longer test the screens' own loading states.
   - **Why:** the shell's chunk fallback `ScreenLoading` (`App.tsx:488`, `:562`) is a `Skeleton`, which has `role="status"`. While the lazy `screens` chunk loads, `getAllByRole("status")` passes on that fallback alone, before the screen mounts.
   - **Red runs don't prove them either:** these checks never failed. In log 37, all 17 pass on `main`; only 6 "alert" checks fail. In the back office, log 38 shows all 42 assertions passing on `main` (the run fails only on unhandled rejections), so that matrix proves only that those rejections are now handled.
   - **Fix:** wait for the chunk to resolve first, or assert the screen's own skeleton label (e.g. `census:myDogs.loading`), not just any status.
2. **major** Step 4: empty states are not done or tested. The step asks for empty, loading and error states on every list and detail of both apps. The report and both matrices cover only loading and error; the only empty-state mention is that `ErrorState` is "the empty state of a failed read". Nothing renders each list with a `200 []` answer. **Fix:** add an empty-answer column to both matrices (asserting `EmptyState`), and fix the lists that fail it.
3. **major** DoD and Verification: the required runs are not shown.
   - **CI:** "CI is green on the final commit" has no run id or result for `85c4b46` or its PR. The report says PR #7's first CI failed, and no later green run is cited. `pr:` is empty in the front matter.
   - **`pnpm e2e`:** AGENTS session protocol step 5 asks for the full suite (all three projects) before `awaiting_verification`. Only `apps/clubs`' MSW suite ran (log 57). The clubs-admin and course-ui e2e were edited (`audit.spec.ts`, `harness.spec.ts`) but not run, and 219 es strings changed.
   - **`e2e:core`:** not run (ruling E110), so INC-56 is only typechecked.
   - **Fix:** the organizer should check the CI run on `main` for this commit before verifying.
4. **minor** `apps/clubs/src/App.tsx:63` + `src/sw.ts:52-60`: a failed lazy import blanks the whole app, which is what INC-41 is meant to prevent.
   - **Cause:** 28 screens are now one lazy chunk, and nothing catches a failed import (no error boundary, no `vite:preloadError` handler).
   - **When it bites:** with A38 a tab stays alive across deploys. The worker does `skipWaiting` + `clients.claim` + `cleanupOutdatedCaches`. After a deploy, an old tab's first `import("./screens-<old>.js")`, or the later `CoursesRoute`/3D import, can 404. React then unmounts the whole tree, and `lazy` keeps the rejected promise.
   - **Fix:** an error boundary around the route `Suspense` that shows `ErrorState` and reloads the document.
5. **minor** `apps/clubs/src/App.tsx:562`: screens with the same route pattern don't remount. The `Suspense` key is the route pattern, so moving in place to the same pattern with a different query keeps the old state. Several screens read the query only at mount: `HistoryPage.tsx:109-110` (`dogId`, `tipus`), `DayPage.tsx:138-141` (`date`, `instructorId`), `InactivityPage.tsx:81` (`periodId`), `BookPage.tsx:154` (`dogId`).
   - **Example:** on `/historic?tipus=X`, tapping the «Històric» tab shows `/historic` with the filter still applied. Before A38, every link was a full load, so this could not happen.
   - **Fix:** key on `pathname + search`, or have those screens follow `popstate`.
6. **minor** `apps/clubs/src/App.tsx:515`: Back no longer restores the scroll position.
   - **Cause:** the content's `scrollTop` is reset to 0 on every `pathname` change, including `popstate`. Under full loads, the browser's back-forward cache restored the position.
   - **Same cause, other symptom:** `UnsubscribePage.tsx:52`'s `/perfil#avisos` now opens in place at the top, not at `#avisos`.
   - **Fix:** reset the scroll only on push and replace navigations, not on `popstate`, and scroll to the hash target when there is one.
7. **minor** `packages/ui/src/branding.tsx`: theme `auto` is not fully live, which contradicts the report ("live … also picks the dark logo").
   - **Logo:** `resolveBrandingLogo` (`:118`) reads `matchMedia` at render time. The context value doesn't change when the scheme flips, so logo consumers don't re-render.
   - **Accent:** the provider's `themeProperties(branding.theme, dark)` (`:346`) passes no `productDark`. The provider's cleanup snapshot therefore misses the swapped accent, and cleanup doesn't restore `data-scheme` or the `theme-color` meta.
   - **D19 preview:** `brandingThemeStyle` (`:288`) ignores the dark scheme, so it always previews `auto` as light.
   - **Fix:** put `dark` in the context value (or a hook) and restore all three attributes on cleanup.
8. **minor** Step 6: TTI is measured only on 01, the lightest screen.
   - **What ran:** an anonymous visitor on 01, with every api route except `/branding` answering 401. The margin under 3 s is 19–126 ms.

   - **Budget:** the "clubs initial JavaScript" budget misses `shared-*.js` (the executor raised this).

9. **minor** `packages/api-client/src/pending-contract.test.ts:27-45`: `publishedElsewhere` will flag legitimate future entries.

   - **Fix:** compare by `$ref` target or by name plus property types, or drop the heuristic.
