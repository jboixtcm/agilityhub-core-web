# Review E8-W03 — needs changes

## Findings

1. **major** `apps/clubs-admin/src/census/InactivityLeavePage.tsx:416` — Date, month and NPS filters expose operators that their single-value selector cannot encode. For example, `between` sends one bound, and `toMonth:exists` sends a month instead of a boolean. These controls cannot express the advertised filters (step 6; `CONVENCIONS_API` §4). Add operator-appropriate inputs and test submitted filters and resulting rows. The Round 3 test at `InactivityLeavePage.test.tsx:84` only checks that options exist.

2. **minor** `apps/clubs-admin/src/census/CensusRecordPage.tsx:1417` — Every successful payment edit sets `accountMissing: false`. With the newly supported partial SEPA update, changing only the holder preserves an existing missing IBAN, yet removes “Compte no informat” until reload. This contradicts R-03-07/E42. Refresh the overview or derive the flag from the returned payment method; test a holder-only edit when the account is missing.

3. **major** `packages/api-client/src/mocks/member-billing-handlers.ts:450` — Lifecycle writes still leave the mock projections inconsistent. PATCH changes the period without appending history or updating D10/D5; future termination similarly leaves the overview unchanged. In-memory reproduction changed an open ACTIVE period to November while its overview still had `date: null` and history stayed empty. Creation also always returns APPROVED, including the current month, without updating the member. This leaves the browser lifecycle incomplete under step 10 and R-13-04/05/17. Apply each transition and then recompute projections; assert subsequent detail, overview and census reads.

4. **minor** `packages/api-client/src/mocks/member-billing-handlers.ts:471` — The `inactivityNoCancelBookings` scenario returns `false` from the parameter endpoint, but approval reads the underlying fixture’s `true` value. Calling the actual handler in that scenario returned two cancelled bookings, while the UI reports they were retained. This contradicts R-13-06 and the explicit step-10 scenario. Use the same effective parameter value for reads and mutations, and test the scenario without overriding its decision handler.

5. **minor** `packages/api-client/src/mocks/member-billing-handlers.ts:215` — Initial D5 and D10 fixtures disagree. Joan has a `PACK_EXPIRED` planned leave in D10 but no `censusMembers` row, so synchronization cannot include him in “Baixes previstes”. Montse initially appears there despite her lifecycle request being PENDING. The committed D5 screenshot shows only Montse, and the Playwright test merely asserts her presence. Initialize both projections from the same fixtures and cover the required planned-leave sources (R-13-17, T-13-22, steps 7/10).

6. **minor** `packages/api-client/src/mocks/member-billing-handlers.ts:480` — Inactivity end dates are constructed as `${toMonth}-31`, also at line 176. November and February therefore produce invalid plain dates, which the date formatter rejects. Step 1 and S13 §13-1 explicitly require the actual last day of the month. Use calendar-aware month-end calculation and cover February and a 30-day month.

7. **minor** `packages/api-client/src/mocks/member-billing-handlers.ts:306` — Queue comparisons stringify NPS values: reproduced results include `10 >= 8 → false` and `10 < 2 → true`. The queue handlers also ignore `sort`; an ascending month request returned October before August, matching the committed screenshot. The mocks therefore cannot validate the list behavior required by steps 6/10. Compare numeric fields numerically and apply the requested ordering before pagination, with result assertions.

8. **minor** `apps/clubs-admin/src/census/InactivityLeavePage.tsx:146` — “Whole queue” filter values come only from page 0 with size 1000; pagination metadata is ignored. Once historical records exceed that page, later members/dates disappear from the selectors and counts become incomplete. Fetch every page or use a contract-supported facet endpoint, and test multiple pages. The report’s claim of complete queue facets is currently broader than the implementation.

9. **minor** `apps/clubs-admin/src/census/InactivityLeavePage.tsx:458` — Applied-filter chips expose raw API values and sometimes raw field names. The committed screenshot displays `REQUESTED,APPROVED,ACTIVE`; fields such as `fromMonth` also fall back to their API name because the locale key is `from`. This violates AGENTS rule 1 and S13 §10. Reuse the localized column labels and format enum, member and date values in ca/es/en.
