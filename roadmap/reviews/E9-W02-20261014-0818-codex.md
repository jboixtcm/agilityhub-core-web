# Review E9-W02 — needs changes

## Findings

1. **major** `packages/api-client/src/core-api-store.ts:396` — Upload retries change the request body while retaining its idempotency key. Each call requests another upload URL/file key, then includes that new `sourceFileKey` in `POST /courses`. A read-only probe reproduced identical keys with `source-1` and `source-2`. After a committed response is lost, this produces `IDEMPOTENCY_KEY_REUSED/DIFFERENT_REQUEST` instead of recovering the result (CONVENCIONS_API §7). Preserve the uploaded file key and complete creation payload across retries.

2. **major** `packages/api-client/src/core-api-store.ts:78` — Persisted obstacle headings omit the Smarter angle convention conversion. The parser retains Y-down angles, and `Planner3D.obstacleHeadingY` negates their Y component; `placementRotation` does not. A probe produced persisted **+30°** versus rendered **−30°** for the same obstacle. This makes the saved AR geometry disagree with the preview (R-16-01/05). Put the conversion in `course-core`, share it between persistence and rendering, and test rotation/mirror combinations.

3. **major** `packages/api-client/src/core-api-store.ts:353` — Door saves bypass optimistic locking against the geometry the user edited. The adapter fetches the latest version but replaces **all** doors with the older form contents. A probe confirmed that another editor’s added door disappeared and their renamed door reverted, while submitting the latest version. This contradicts CONVENCIONS_API §7 and the report’s “only edited doors” claim. Submit the original version, or merge explicit changes against the original and latest door lists with conflict detection.

4. **major** `packages/course-ui/src/lib/storage/types.ts:97` — `SavePlacementInput` has no `force`, and `savePlacement` never sends it. Consequently, an administrator cannot save a placement containing critical warnings, even after confirmation; the published contract requires `force: true` (R-16-05). Expose and forward this field, with tests for normal rejection and the authorized override.

5. **major** `packages/course-ui/src/lib/storage/types.ts:261` — The replacement `PlannerStore` omits build-session completion. The source store supports ending a build, and the snapshot publishes `POST /build-sessions/{id}/finish`, but this adapter only creates, reads and updates obstacles. This leaves the R1 session lifecycle incomplete under task step 2 and R-16-11. Implement completion through the store with its caller-owned idempotency key.

6. **major** `packages/course-ui/src/components/RingMarkerDiagram.tsx:65` — The diagram silently relocates authoritative Core API markers using a Supabase migration heuristic. For the arrangement in the new test, marker A stored at `(0,0)` is displayed at `(0,20)`, while `listMarkers` and the course renderers retain its actual coordinates. This can give installers conflicting calibration instructions (R-16-04). Render Core coordinates unchanged; any legacy migration needs explicit provenance and consistent persistence.

7. **major** `packages/course-ui/src/components/ui/Button.tsx:13` — Primary controls use `bg-primary text-text`. In the default theme both resolve to `#1d1d1f`, giving **1:1 contrast**; `UnitsToggle` and filled `IconButton` repeat this pairing. Save, continue and placement controls therefore lose readable labels (AGENTS rule 6). Use the existing `primary-fg` token or shared UI components.

8. **major** `packages/ui/src/tokens.css:66` — Both `--ah-color-course-obstacle-dark` and `--ah-color-course-text` resolve to the same text color. `Planner3D.makeTextSprite` uses these as the number badge’s background and foreground, leaving only the background’s slight transparency to distinguish the digit. This breaks readable course numbering and AA contrast (AGENTS rule 6). Define contrasting badge foreground/background tokens and verify them in both themes.

9. **minor** `packages/course-ui/src/components/RingDoorEditor.tsx:424` — A successful save updates the parent ring but never replaces the local drafts. Newly added doors retain `id: undefined`; the returned ring contains generated IDs, so the editor remains dirty and subsequent saves generate replacement IDs again. Rebuild the drafts from the saved response and test add → save → edit → save, including stable IDs and the success state.

10. **minor** `packages/course-ui/src/components/RingDoorEditor.tsx:427` — API errors are discarded and reduced to one generic label. `UploadCourse` and `RingInventoryEditor` do likewise, preventing catalog-specific messages for `STALE_VERSION`, `GEOMETRY_INVALID`, `FILE_TOO_LARGE` and other actionable failures (AGENTS rule 4). Retain the error and expose a caller-supplied error formatter or use the shared catalog mapper.

11. **minor** `packages/course-ui/src/components/ui/Button.tsx:17` — Literal Tailwind colors remain: `bg-red-700`, `text-white`, `hover:bg-red-600`, plus `bg-red-600/20` in `Badge.tsx:5`. These bypass club theme variables despite the report’s claim that colors were migrated (AGENTS rule 2). Replace them with semantic tokens and extend lint coverage to these utility classes.

12. **minor** `packages/course-ui/src/components/WarningsPanel.tsx:60` — Every non-null `distanceMeters` is formatted as a length, but the recovered inventory rule puts **missing equipment counts** in that field. A shortage of two tunnels therefore receives a misleading metre/feet annotation. Format this metadata by warning rule, or omit the distance annotation for inventory warnings (R-16-05/12).

13. **minor** `packages/course-ui/src/components/PlacementControls.tsx:120` — The localization boundary is incomplete. `formatLength` uses `toFixed`, so Catalan/Spanish step labels retain decimal points; `RingMarkerDiagram` also renders raw numbers, and `WarningsPanel.tsx:59` exposes untranslated identifiers such as `door-clearance`. Supply locale-aware formatters and translated warning labels (R-16-17, CONVENCIONS_I18N §1).

14. **major** `packages/course-ui/tests/port.test.tsx:18` — The required T-16-04 rendering and interaction evidence is missing. These tests never render either course viewer, contain no fixture snapshots, and never assert that placement interaction updates geometry **and warnings**. Neither adapter upload nor `savePlacement` is exercised by `core-api-store.test.ts`; the retry test mocks the adapter entirely. The existing app Playwright tests do not import `course-ui`, so their passing counts cannot validate this port. Add the specified fixture/rendering coverage, payload-level adapter tests, and browser evidence for the changed visual components.
