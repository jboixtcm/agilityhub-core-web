# Review E8-W01 — needs changes

## Findings

1. **major** `apps/clubs-admin/src/billing/BillingPage.tsx:293` — Card-charge completion can leave D6 permanently showing `CHARGING`. If the page previously loaded `GENERATED`, the period then reports `CHARGING`, and the next detail response is already `COMPLETED`, `lastRunStatus` takes precedence over the period. Consequently, `settled` is false and neither the period nor invoices refresh. Subsequent responses—and [Actualitza]—cannot recover because the remembered status is now `COMPLETED`. This misses R-12-13 and Round 2 point 3. Treat a completed detail response against a charging period as requiring reconciliation; add a regression starting from an already-loaded `GENERATED` run.

2. **minor** `apps/clubs-admin/src/billing/BillingPage.tsx:362` — Selection cleanup still retains paid receipts when a status filter removes them from the response. Select a receipt under «Pendents», pay it in its drawer, then bulk-pay the remaining selection: the paid receipt is absent from `items`, so its selected ID survives and the entire batch receives `409 INVALID_STATE`. Refetching repeats the problem. R-12-16 / Round 2 point 4 remains partially addressed. Remove affected IDs after successful drawer actions and test this flow with the `PENDING` filter active.

3. **minor** `apps/clubs-admin/src/billing/RemittancesPage.tsx:132` — Default saved views still fail under the application's development `StrictMode` (`src/main.tsx:72`). The first effect sets `urlWritten.current`; the repeated mount effect writes pagination/fields before `/saved-views` resolves. `useSavedViews` then rejects the default because the URL is no longer bare. The new test omits `StrictMode`, so it misses this failure of Round 2 point 5. Gate URL synchronization on completed default-view initialization, rather than skipping one effect invocation.

4. **minor** `packages/api-client/src/mocks/fixtures/billing.ts:253` — The incident and cash-member «Obre fitxa» links reference billing-only `b100…` IDs that the member-overview mock does not serve. `packages/api-client/src/mocks/handlers.ts:2754` therefore returns `404`, preventing the required D6 → D10 flow under MSW. This leaves step 4 and the MSW Definition of Done incomplete. Seed matching member records or reuse supported census IDs, and test navigation through to the loaded record.
