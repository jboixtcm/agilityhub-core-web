# Review E7-W02 — needs changes

## Findings

1. **major** `apps/clubs/src/profile/preferences-saver.ts:101` — Leaving the page can lose preference changes. If one PUT is pending, `flushNow()` clears the debounce but returns without sending the queued edit. When the first response arrives, the queued edit inherits `keepalive: false`; nothing persists it across navigation. A read-only probe reproduced this with successive reminder values of 60 and 120. This violates step 4’s immediate-save behavior and R-11-04. Preserve pending edits across teardown, scoped to account and club, and test reload/navigation during a delayed PUT.

2. **major** `apps/clubs/src/notifications/push.ts:154` — Logout does not account for an in-flight subscription. Before the POST returns, no subscription ID is stored, so logout skips DELETE. The POST can then complete and leave an active subscription after logout. The probe produced `POST in flight → logged out → subscribed`, with no DELETE and an ID stored afterward. This violates R-11-07 and step 5 and can leave the device receiving the former session’s notifications. Coordinate subscription completion with logout and clean up late subscriptions without indefinitely blocking logout.

3. **major** `apps/clubs/src/NotificationsPage.tsx:75` — Read-all failures are silently abandoned: resetting `readAllSent.current` triggers neither another request nor an error/retry control. Loading another page does not retry it either. Successful responses also only update a ref; their `unreadCount` never updates the feed or informs Home. Returning home before completion can therefore leave its previously fetched counter stale. Step 2 explicitly requires retryable reads and counter synchronization. Add a retryable mutation and shared read-state update; test failed and delayed read-all responses.

4. **major** `apps/clubs/src/NotificationsPage.tsx:250` — `CLAIM_SEAT` is rendered without checking `WAITLIST`. A historical notification containing the three IDs still exposes the button after that module is disabled. A component probe with no enabled modules rendered an enabled claim button. The mock conceals this by removing these notifications in `notification-handlers.ts:100`. AGENTS rule 3 and `CATALEG_MODULS.md` require screen 11 to hide this action. Gate the button and test a historical N-15 returned while WAITLIST is off.

5. **minor** `apps/clubs/src/profile/NoticesCard.tsx:39` — The denied-permission explanation disappears after navigation or reload because `pushDenied` always starts as `false`. A returning member with permission already denied and `pushClubNews: true` sees an enabled preference without the required explanation. The headless-browser workaround changes production behavior contrary to R-11-07. Read the existing permission state without prompting, and isolate the browser-test discrepancy in the test setup.

6. **minor** `apps/clubs/e2e/notifications.spec.ts:47` — The required three-locale branch coverage is missing. Every E2E initializes Catalan; component coverage adds a Spanish language-switch case, while English appears only in formatter assertions. Translation-key parity does not demonstrate the Definition of Done’s ca/es/en screen branches. Add localized feed, preference, unsubscribe, and module-off checks, and record their evidence.
