# Review E9-W05 — minor issues

## Findings
1. **minor** `e2e/core/e9-core.spec.ts:870-880` — When no booking is usable on the run's day, the T-16-16 core test skips the whole 07 leg. It only adds an annotation, starts the session through the api, and still passes. That leg is the part Step 2 and organizer point #8 ask for (07 «Recorregut previst» → [Sessió de muntatge] against the real core), so a green `e2e:core` can hide it. It did run in the final run (`e9-core-planned-07.json` has `sessionId`). Two earlier attempts (`42`, `45`) passed without it, which shows how easy the skip is. · Suggested fix: fail the test, or make the skip clearly visible as `test.skip`/`test.fixme` with the reason, so the organizer's verification of a later run cannot mistake it for coverage.
2. **minor** `e2e/core/e9-core.spec.ts:836-842` and `plannedClassOf` — The test changes shared core state:
   - It promotes the seeded `member@example.test` to MEMBER+INSTRUCTOR. The `finally` puts the roles back, but if the run is killed or times out, the member keeps INSTRUCTOR and the other stages (E4…E10 run on the same stage) would see a staff member.
   - It also books a class, PATCHes `placementId` onto it, and stores a canonical geometry on a ring that had none, with no cleanup. That breaks the "ring with no geometry" precondition for any later run.
   - An `expect` inside `finally` replaces the original failure when both fail.
   · Suggested fix: use a dedicated seeded staff+member account, or undo the booking/plan in `finally`, and do the role reset without an `expect` that can mask the first error.
3. **minor** `packages/api-client/openapi/openapi.next.json` — The snapshot was adopted, but the staged `openapi.next.json` (and `.sha`) were left in place, identical to `openapi.json`. Earlier adoption tasks deleted the staged file (e.g. `98aba33`, `11fea96`), and AGENTS rule 4 says the adoption task swaps it in. · Suggested fix: remove the staged pair as earlier adoptions did, or have the organizer confirm that leaving it is fine.
4. **minor** `scripts/check-clubs-bundle.mjs:16` — The #5 check matches chunk **file names** only (`admin-*-<8 chars>.js`). If Rollup merges a namespace JSON into another chunk (`experimentalMinChunkSize`, `manualChunks`, or an eager import), the namespace still ships in `apps/clubs` and the check still passes. · Suggested fix: also grep the chunk contents for one sentinel key per forbidden namespace, or assert on Vite's `manifest.json` module ids.
5. **nit** `apps/clubs-admin/src/instructor/AgendaRingSetups.tsx:41-43` — The comment says the history fallback lets "the orientative AgilityHub level stand in". But `ringSetupSummary` (`packages/api-client/src/ring-setups.ts:22`) sets `levelLabel: null`, so the D12 strip for an ADMIN-only session shows no level at all. `setupText` already turns `EASY/MEDIUM/HARD` into translated labels, so passing `agilityhubLevel` would be safe (it would not leak a raw code). · Suggested fix: either pass the level or correct the comment.
6. **nit** `roadmap/evidence/E9-W05/e9-core-seeded-e9-w05 07.json` — The file name has a space in it, because the label `"E9-W05 07"` is used as the file name. · Suggested fix: slugify the label in `note()`/the seed helper.
7. **nit** `apps/clubs/e2e/courses-gallery.spec.ts` and `apps/clubs-admin/e2e/courses-gallery.spec.ts` — The 20 gallery tests (3D canvas plus a fixed 1.5 s wait each) now run on every `pnpm e2e`, including CI. They overwrite `roadmap/evidence/E9-W05/*.png` every time. They are mostly capture scripts with few rule assertions. · Suggested fix: gate them behind `E2E_CAPTURE_TASK`/a tag so normal runs don't pay for them, or accept the cost as a documented decision.

The api would still accept it, but the button invites building something that is already up. · Suggested fix: hide it when `setup.placementId === planned.placementId`, or leave it as is and note the choice under assumptions.
