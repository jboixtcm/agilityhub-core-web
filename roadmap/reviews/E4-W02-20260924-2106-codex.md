# Review E4-W02 — needs changes

## Findings

1. **major** `apps/clubs-admin/src/planning/calendar-shared.tsx:55` — Time options start at the opening minute instead of a valid slot boundary. With permitted opening hours `07:05–22:00` and `classes.slotMinutes=10`, every offered time ends in `:05/:15/…` and fails `INVALID_SLOT_GRANULARITY`. This prevents class/block creation and valid time changes. S02 R-02-09 allows five-minute opening-hour granularity; S06 requires slot-aligned times. Round the first option up to a slot boundary and add regression tests for `07:05` openings.

2. **major** `apps/clubs-admin/src/planning/SelectedClassCard.tsx:286` — The editor unlocks after `STALE_VERSION`/`INVALID_STATE` while the calendar refetch is still pending. Unlike success, these branches never set `awaitingVersion`. Reproduced: after a 409, a new capacity edit is accepted, then silently discarded when the refreshed version remounts the card (`CalendarPage.tsx:768`). This leaves the round-3 “no edit lost … until the refreshed version is applied” requirement incomplete. Keep editors locked through conflict recovery, including `toggleExempt`, and test a delayed refetch after 409.

3. **minor** `apps/clubs-admin/src/planning/calendar-shared.tsx:244` — An omitted weekday becomes open `07:00–22:00`, although S02 R-02-09 defines an absent day as **closed**. The forms offer scheduling on closed days; `packages/api-client/src/mocks/calendar-handlers.ts:259` repeats the fallback and accepts requests the contract prohibits. Represent closed days explicitly, prevent submission there, and make MSW enforce the same rule. Add a test with Sunday omitted from `club.openingHours`.
