# Review E3-W06 — needs changes

## Findings

1. **major** `apps/clubs/src/SignupPage.tsx:2481` — Routed errors can still disappear during full navigation. `navigateTo()` updates React’s `path` before calling `location.assign()`. While the destination document loads, the old page can render the destination step, consume `pendingError` (`:332`), and persist its removal. Reproduced with the actual component in an in-memory harness: the error existed at navigation start, disappeared before unload, and was absent after remount. The test’s immediate microtask cleanup hides this interval. This violates step 3 and round-2 requirement 1. Avoid rendering/consuming the destination error in the departing document; add a delayed-navigation regression test.

2. **major** `apps/clubs/src/SignupPage.tsx:2394` — Every reload of `?cs=cancel` deletes the checkout key, including a key belonging to a **subsequent retry**. Reproduction: cancel checkout → retry → checkout response lost → refresh → retry. The saved key becomes absent after refresh, and the next request uses a different key. This defeats step 2’s stable retries and CONVENCIONS_API §7, potentially creating another checkout instead of replaying the existing session. Consume the cancellation marker once, or associate cancellation with the specific attempt; test this sequence across remounts.

3. **minor** `apps/clubs/src/SignupPage.tsx:913` — A passport-only applicant’s `INVALID_ID_DOCUMENT` is displayed against—and focuses—the empty DNI/NIE field. The passport control (`:931`) receives neither the error nor `aria-describedby`. This leaves step 3’s field mapping and step 6’s accessibility requirement incomplete. Route document errors to the active document input and add a passport-error test.
