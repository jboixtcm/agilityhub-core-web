# Review E4-W11: minor issues

## Findings
1. **minor** `packages/api-client/src/mocks/activity-handlers.ts:818-824` together with `apps/clubs-admin/src/activities/ActivityPage.tsx:687-704`: the real api refuses the D7 publication at a step the mock never checks.
   - **The mock:** the new `openingHoursProblem()` runs only on `POST …/publication` and on a re-syncing PATCH. `GET /activities/{id}/ring-conflicts` still always answers 200.
   - **The api:** `ActivitiesController.ringConflicts` → `ActivityLifecycleService.conflicts` (`:54`) → `ActivityContext.blockRequest` (`:47-55`) → `RingBlockWindow.of` (`:15`). That chain throws `422 OUTSIDE_OPENING_HOURS` (and `400 INVALID_TIME_RANGE`) for the same window.
   - **In D7:** `startPublish` calls that preview before the POST. Against the api, a window outside the hours therefore fails at the preview and shows as a general toast (`setFeedback`). It never reaches the publication error that the new mock test covers.
   - **When it happens:** when the opening-hours read failed (then `closedDay` is false and [PUBLICA] stays enabled), or when a saved time is outside a changed opening window (`withValue` keeps it).
   - **Why it matters:** the fixed convention «Mocks behave like the api».
   - **Contract gap:** S07 §6 lists only `200` for `ring-conflicts`, and the api's `@ContractErrors` does not declare 422 either.
   - **Fix:** make the mock preview answer like the api, and have `startPublish` place `OUTSIDE_OPENING_HOURS` on date/start/end as `saveErrorTargets` does. Or route the contract gap (spec vs api) to the organizer.

2. **minor** `apps/clubs-admin/src/planning/SelectedClassCard.tsx:379-510` and `planning/planning.css:306`: the chips are disabled on a closed day, but they don't look disabled.
   - Only `.planning-chip:disabled` has a style. The `.calendar-chip` editors (Pista, Nivells, Instructor, Límit, Hora, Descripció) have none.
   - `roadmap/evidence/E4-W11/D4-classe-diumenge-tancat-xips-desactivats-1280.png` (chips disabled) and `E4-W10/D4-classe-diumenge-tancat-notes-1280.png` (chips enabled) look identical in the chip area.
   - **Why:** review #6 was about the admin not being told that only «Notes» can be saved. Now the chips look editable but do nothing when clicked.
   - **Fix:** add a token-based disabled look, e.g. `.calendar-chip:has(:disabled)` with `--ah-text-muted`/opacity and `cursor: not-allowed`.
