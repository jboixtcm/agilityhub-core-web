# Review E3-W07 — needs changes

## Findings

1. **major** `apps/clubs-admin/src/dashboard/SignupReviewPage.tsx:149` — Reloading does not immediately invalidate the previous quote or disable validation. Reproduced with an in-memory React probe: successful quote → `STALE_VERSION` → reload leaves the old upfront block visible and `VALIDA` enabled. Rejecting that reload leaves the same state, without a load error. `currentQuote` becomes invalid only after a successful response replaces `signup`. This leaves round-2 point 2 incomplete and permits decisions against known-stale payment information. Invalidate the quote when reload starts, block validation until reload and requoting succeed, and expose reload failures with retry. Add delayed-response and failed-reload tests.

2. **minor** `apps/clubs-admin/src/dashboard/SignupEditDrawer.tsx:423` — The payment selector treats every provider key as available, ignoring `enabled` and `configured`. An in-memory probe with `STRIPE: { enabled: false, configured: false }` still offered `CARD`. This contradicts R-04-10 and round-2 point 3’s requirement to offer available methods. The seed’s inconsistent flags do not establish that every configured provider is active. Resolve availability through an authoritative API field or corrected provider flags, and test that explicitly disabled Stripe is excluded while preserving the applicant’s existing method.
