## Findings
1. **minor** `apps/clubs/src/profile/preferences-saver.ts:115,159,198`: once `leave()` has run, `left` stays `true` for the life of that saver.
   - **How it happens:** screen 12's links (`/gossos`, `/dades`, the tab bar) are plain `<a href>`, so they reload the whole page. If the member leaves with an unsaved change, `pagehide` calls `leave()`. If Back then restores 12 from the browser's page cache (bfcache), the same saver is reused, and two paths now lose a change:
     - an edit queued behind a `PUT` that is still out is never sent, because `finally` skips the flush when `left` is true;
     - the next `leave()` returns early, after clearing the running 300 ms timer. So the last change is neither sent nor kept in the outbox.
   - **Why it matters:** this is the same "leaving 12 never loses a preference" rule as item #1 (R-11-04, step 4).
   - **Fix:** reset `left` on `pageshow` when `persisted` is true, or make `leave()` depend on what is still unsaved instead of firing once. Test: `pagehide` with a change pending → `pageshow` with `persisted` → an edit while a `PUT` is out → leave → the edit is saved.
2. **minor** `apps/clubs/src/NotificationsPage.test.tsx:335` and `notifications/unread.ts`: the test for item #3 ("a read-all answered after going back Home updates the bell there") goes back Home inside the same JS document.
   - `cleanup()` + `renderApp("/inici")` keeps the module-level `useUnreadCount` store alive.
   - In the app, every way back to 03 is a full-page `<a href>`: the tab bar (`packages/ui/src/components.tsx:493`, no `onClick`) and `BookingDetailPage`'s back link. So the store starts fresh, and 03's first `GET /me/home` can run before the `keepalive` read-all lands. The bell then shows «2 sense llegir» until 03 loads again.
   - The executor disclosed this as R2-A1. Still, item 3's criterion ("a delayed answer after going back Home → Home shows 0") holds only for navigations the app never makes.
   - **Fix:** either store a "read-all pending" marker in `sessionStorage` that 03 honours (send read-all again, which is idempotent, then read `/me/home` again), or have the organizer accept R2-A1 explicitly. Either way, the test name should not claim the production path.
3. **nit** `apps/clubs/src/booking/shared.ts:79-101,108-124`: a quiet refetch of 03 can replace its rows with the error screen.
   - Both triggers use it: a published read-all (`refresh`) and the round-1 `pageshow` handler.
   - When that refetch fails, `useLoader` sets `status: "error"`, so 03's rows give way to its error screen. The `useMeHome` doc comment says "the rows stay on screen".
   - **Fix:** keep the last data on a failed quiet reload.
4. **nit** `apps/clubs/src/profile/preferences-saver.ts:149` / `writeNoticesOutbox(undefined)`: the outbox is scoped to account and club, not to one visit.
   - When an older visit's `PUT` succeeds, it clears the entry. That can erase an entry a newer visit's `leave()` wrote in the same tab (12 → away → 12 → away quickly, then the tab dies).
   - The window is narrow. Tagging entries with a visit id would close it.
5. **nit** `apps/clubs/src/profile/NoticesCard.tsx:43`: an impersonated session can show «Activa les notificacions al navegador…».
   - It reads the admin's own browser permission at mount and may show the note, but `askForPush` never asks during impersonation (assumption 6), so the note gives the admin advice that does not apply.
   - **Fix:** skip the note when impersonated.
