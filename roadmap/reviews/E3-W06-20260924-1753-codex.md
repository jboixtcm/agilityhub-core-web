# Review E3-W06 — needs changes

## Findings

1. **major** `apps/clubs/src/SignupPage.tsx:2405` — Cross-step errors disappear during production navigation. `routed` exists only in React state, but `navigateTo()` calls the production navigator, which uses `window.location.assign()` (`App.tsx:1111`). The destination therefore mounts without the field error, inline message or focus instruction. The M2 table tests hide this by using `vi.fn()` for navigation. This breaks step 3 and the Definition of Done. Preserve error state across navigation or use client-side navigation; add a browser test asserting the error and focus after arrival.

2. **major** `apps/clubs/src/SignupPage.tsx:1890` — After signup succeeds, checkout cancellation/failure leaves the payment fields, start option and consents editable, but subsequent submission skips building/comparing the payload whenever `submission.memberId` exists. Changes are silently ignored; checkout uses the original server submission. For example, selecting a different start option changes the displayed choice without changing what checkout charges. This undermines R-04-26 and step 2. Make the committed submission explicit and its fields read-only during checkout retry, or implement a supported update flow. Test edits after cancellation.

3. **major** `apps/clubs/src/SignupPage.tsx:1918` — `submission.fingerprint` stores the entire request as plaintext JSON, including the IBAN. After a failed submission, switching to cash removes `payment.iban` but retains the IBAN inside this persisted fingerprint (`:2041`). Step 6 explicitly requires the IBAN to leave the session draft. Use a non-reversible payload digest and test removal **after a submission attempt**. Also clear SEPA-only fields when configuration reload changes the method (`:2358`).

4. **minor** `apps/clubs/src/SignupPage.tsx:1600` — Clearing a previously FOUND family claim leaves the former group holder as the account holder. Every field edit immediately sets `familyFound=false`, so the reset condition at `:1621` cannot succeed when both fields have been cleared. PaymentStep then preserves the non-empty stale holder. Under R-04-10, the default should return to the applicant. Track whether the holder was automatically populated and reset that value when the claim is invalidated; test FOUND → clear both fields → continue.

5. **minor** `apps/clubs/src/SignupPage.tsx:185` — The new birth-date and birth-month checks use the browser’s calendar date rather than the club’s. At day/month boundaries, applicants in another timezone can receive incorrect validation results. S04 §4 defines “today” in `CLUB.timeZone`; the report’s assumption does not change that convention. Use the club date, preferably the configuration’s `upfront.today`, and test differing browser/club dates.

6. **minor** `e2e/core/e3-signup.spec.ts:484` — Real-core coverage adds NIE submission but no passport-only submission. The helper still fills the DNI/NIE field, and the two applicants cover DNI and NIE only. The Definition of Done explicitly requires **both NIE and passport-only applicants in real-core e2e**. Add a passport-only flow asserting the submitted document and successful confirmation.

7. **minor** `packages/api-client/src/mocks/handlers.ts:808` — The new mock validator rejects valid R-04-01 inputs: seven-digit DNI `1234567L` is not zero-padded, and `OTHER` is always rejected because both handlers unconditionally use Spanish validation. This makes the mocks diverge from the country-profile contract. Normalize short DNI values and select validation by profile; add success assertions for GENERIC `OTHER` and the short-DNI example.

8. **minor** `roadmap/tasks/E3-W06.md:235` — The first failed turbo log was overwritten, so the required evidence is incomplete. AGENTS.md and the task’s fixed conventions require a committed log for every failed attempt; the prose summary cannot replace it. Recover the original output if available, otherwise explicitly record this as an evidence exception for organizer acceptance.
