# Review E6-W01 — minor issues

Round 2 fixes all seven organizer points. Each one has a test that the committed log `12` or `13` shows failing before the fix and passing after it (logs `14` and `15`). No blocker or major finding. One minor edge case remains on screen 21, plus three nits.

## Findings
1. **minor** `apps/clubs/src/instructor/useAttendanceSheet.ts:93` (with `packages/ui/src/attendance.tsx:85` `mergeSheet` and `useAttendanceSheet.ts:132` `keyFor`) — After a refused save, the recovery read keeps edits that the fresh sheet no longer allows. Replaying the same save then returns the same refusal.
   - **Scenario:**
     - The instructor marks Marc «present» just before `editableUntil` (B16) and taps [DESA] after it.
     - The api answers `422 ATTENDANCE_WINDOW_CLOSED`, and the sheet read again has `canMarkPresence = false`.
     - `mergeSheet` only drops an edit when the row is `final` or someone else changed it. It never checks `canChooseAttendance`. So the draft `PRESENT` stays checked inside a group of disabled circles, and nothing can undo it.
     - [DESA] stays enabled, because `changes.length > 0`.
     - Every press sends the identical body under the identical `Idempotency-Key`. Keys are stored per payload and never forgotten after the api answers. The executor's own MSW world stores refusals under the key (`attendance-handlers.ts:137-142`), so it replays the stored 422. CONVENCIONS_API §7 says «la segona crida retorna la mateixa resposta» for 24 h.
     - `INSTRUCTOR_NOTICE_DISABLED` behaves the same for a `NOTIFIED` draft; the only way out there is to pick another circle.
   - **Why it matters:**
     - R-10-03: circles outside the window are inert, and the screen should show only what the api allows.
     - Step 4: after these codes, «refetch (nothing was applied)» and «a fresh `Idempotency-Key` per attempt».
     - DoD: «never lets … an out-of-window circle be touched». Here the screen shows, and offers to save, an unsaved state that can no longer be chosen.
   - **Fix:**
     - When rebasing (and in `mergeSheet`, which D12 will reuse), drop any draft entry that `canChooseAttendance` refuses under the permissions of the sheet just read.
     - Keep the payload key only after a network failure (status 0). Once the api has answered, forget it.
     - Test: PUT → `422 ATTENDANCE_WINDOW_CLOSED`, the next read comes back closed → empty draft, [DESA] disabled, and a later save sends a new key.
2. **nit** `packages/ui/src/attendance.tsx:85` — `baseRows` defaults to `[]`, which quietly switches off the "someone else changed this row" check (A8, R-10-04).
   - A D12 caller (E6-W03) that follows step 3's three-argument form `mergeSheet(serverRows, draft, touchedIds)` would put the caller's edit back on a row the other person changed.
   - Make `baseRows` required.
3. **nit** `apps/clubs/src/instructor/StudentSearchPage.tsx:46` — the `reading` ref is not reset when the query changes.
   - If «Mostra'n més» is still loading for the old query, a tap on the new query's «Mostra'n més» is silently ignored until the old request settles. There is no spinner and no feedback.
   - Reset the ref, or key it by `requestKey`.
4. **nit** `packages/ui/src/attendance.css:82` — while a save is in flight, every unchosen circle is `disabled`, so every row fades to 0.35 for the length of each save.
   - This is allowed under WCAG 1.4.11, but it is a visual flash on every [DESA].
   - Fade only the circles that are disabled by permission (`final` or a `can*` flag), not the ones locked by `saving`.
