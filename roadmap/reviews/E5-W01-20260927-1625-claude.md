1. **major** `apps/clubs/src/booking/ConfirmPage.tsx:416-433` + `{ca,es,en}/booking.json` `confirm.nextBookableAt` (NEXT branch) — B1's «Podràs reservar aquesta classe a partir de {nextBookableAt}.» is false every time it shows. The cause is what the api puts in `nextBookableAt`. The code follows the 26-09 amendment exactly.
   - **What the api sends:** the 409 carries `weeks.nextBookableAt(session.startsAt())`, which is `week(classStartsAt).end()` (`SeatHoldService.java:73-74`, `BookingWeeks.java:54-55`; unchanged since before snapshot `c70adf9`).
     - That is the end of the class's own week. For a NEXT class it is the start of W2, after the class has taken place.
     - The amendment says «a `nextBookableAt` la classe passa a la setmana en curs». That is only true of the end of the *current* week.
   - **When members see it:**
     - `bookings.maxNextWeek` allows `min: 0` (`catalog.yaml:199-205`). With 0, every next-week row is `WEEKLY_LIMIT_DONE` (`BookableClassesQuery.java:92-93`). Tapping one always shows this note, and the note starts with «La setmana vinent ja tens 0 classes amb la Duna.».
     - With the default 1, it shows whenever next week's counted booking cannot be swapped: late window, late-cancelled, or `PAYMENT_PENDING`. `PAYMENT_PENDING` counts but is never swappable; it lands in `LATE_WINDOW` (`BookingLimits.java:15,34-37`).
   - **The test hides it:** `confirm.test.tsx:272-294` taps row 0, «dc 5», which is a CURRENT class. Log 12's DOM shows the card «Dimecres 5 · 18:50–19:50».
     - It fakes a refusal with `week: NEXT`, the current week's end as `nextBookableAt`, and a `LATE_WINDOW` booking 8 days away. The api never sends that combination.
     - So the test pins a note that contradicts the card above it («… aquesta classe a partir de diumenge 9» under a Wednesday 5 class).
   - **Fix (@organizer):** choose one:
     - an api follow-up to E5-T25 that sends the end of the current booking week (`week(now).end()`; the value is the same for CURRENT);
     - or new NEXT wording.
     Also decide the wording for `limit = 0`. On the web side, rebuild the NEXT test on a next-week row («dl 10») with the value the api would really send. The front must not compute the date itself (Fixed conventions).
