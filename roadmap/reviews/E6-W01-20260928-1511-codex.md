# Review E6-W01 — needs changes

## Findings

1. **major** `apps/clubs/src/instructor/useAttendanceSheet.ts:129` — Recovery reloads can overwrite a later successful save. After a refused PUT, `refetch()` leaves the sheet editable and `finally` clears `saving`. A second PUT can succeed before that GET returns; the GET then unconditionally replaces the newer sheet. Reproduced with the actual hook: version 5/`NO_SHOW` reverted onscreen to version 4/`PENDING`, with an empty draft and “Sheet saved” still displayed. This violates R-10-04 and the task’s recovery requirement. Lock editing through recovery, reject obsolete responses, and add a delayed-GET regression test.

2. **minor** `apps/clubs/src/instructor/StudentSearchPage.tsx:38` — Search always requests the first 50 results and ignores `totalPages`; there is no pagination or load-more control. Matching students beyond that page are silently omitted. S10 step 6 reuses the paginated `/dogs` contract from CONVENCIONS_API §4. Support subsequent pages and test at least 51 matching dogs.

3. **minor** `apps/clubs/src/instructor/StudentSearchPage.tsx:102` — Splitting `owner.fullName` at the first space truncates compound first names, and search rows omit the owner annotation when another guide handles the dog. Both depart from R-10-00. The report acknowledges the first-name contract gap, but it remains unresolved. Obtain a server-projected first name/resolved guide, render the required owner annotation, and cover compound names and differing guides.

4. **minor** `apps/clubs/src/App.tsx:104` — The new task-management module registration is ineffective. `/instructor/alumnes/{dogId}/tasques` resolves to `/instructor/*`; `routePlaceholder()` checks that wildcard against the module registry and finds no required module. Confirmed that the route is considered enabled with TASKS off. This contradicts S10 §9 and AGENTS rule 3. Register an explicit guarded placeholder route or apply module matching to the concrete pathname; test direct navigation with TASKS disabled.

5. **minor** `apps/clubs/src/instructor/AttendancePage.tsx:247` — Read failures discard `ApiError.code` and always show a generic loading error. The same occurs in `DayPage.tsx:226`, `StudentCardPage.tsx:105`, and `StudentSearchPage.tsx:77`, hiding distinctions such as `NOT_FOUND` and `FORBIDDEN`. AGENTS rule 4 and the task’s fixed conventions require catalog messages by code. Use the existing `errorText` helper, with a fallback for non-API failures, and test representative codes.

6. **minor** `apps/clubs/src/instructor/AttendancePage.tsx:42` — `PhotoLightbox` moves focus inside but neither traps it nor makes the underlying page inert. Tab/Shift+Tab can reach attendance controls and navigation behind a dialog declared `aria-modal="true"`; background scrolling is also unrestricted. This misses AGENTS rule 6 and the photo-return requirement. Contain focus, prevent background interaction/scrolling, restore the previous state, and test keyboard navigation.

7. **minor** `packages/ui/src/attendance.css:23` — Enabled, unselected attendance controls use `opacity: 0.22`, making their identifying circles fail AA non-text contrast. With the supplied tokens, the green circle is approximately **1.43:1** against the dark surface and **1.22:1** against white; the selected white tick on green is **2.71:1**. AGENTS rule 6 requires AA. Preserve sufficient contrast for enabled controls and distinguish selection without fading their essential graphics below 3:1.
