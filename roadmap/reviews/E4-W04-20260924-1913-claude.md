# Review E4-W04 — needs changes

## Findings
1. **major** `apps/clubs/src/activities/shared.ts:24` and `packages/api-client/src/mocks/fixtures/activities.ts:~620` — On 03, a start-only activity gets a bogus end time against the real core. When `end == null`, the api sets the end to the next day at 00:00 (`agilityhub-core-api/.../activities/domain/ActivityTimes.java:8`), so `endsAtLocal` is e.g. `2026-09-20T00:00`. `localHours` only treats `end === start` or `"23:59"` as "no end". So the Lliga renders «Dissabte 19 · 9:00–0:00». The tests pass only because the mock invents the `"23:59"`/start-repeat end, which the api never sends.
   - The same mismatch changes the 03 filter (`ActivityReservationRow.tsx:71`, `endsAtLocal > now`). Against the mock, the row disappears at the start time; against the api, it stays until midnight.
   - Breaks R-07-11 / R-07-13 in production.
   - Fix: treat "next-day `T00:00`" as "no end", and make the fixture emit what the api emits.
2. **major** `apps/clubs-admin/src/activities/PublishConflictsDialog.tsx:55-72` + `ActivityPage.tsx:500-504, 527-541, 1393-1412` — The conflict dialog can hang with its spinner on forever.
   - `confirm()` resets `pending` only in its `catch`. But `publishWith` handles `RING_BLOCK_CONFLICT`/`RING_HAS_BOOKINGS` itself and returns normally. In save mode, `save()` swallows every error except `ADMIN_TEXT_REQUIRED` (via `failSave`).
   - The dialog is keyed by `JSON.stringify(preview)`. So when a 409 carries the same conflicts, or no `details` (it falls back to `current.preview`), the dialog does not remount. The button stays loading and no message appears.
   - The same happens in save mode for `STALE_VERSION`, `CAPACITY_BELOW_REGISTRATIONS` and `OUTSIDE_OPENING_HOURS`: the error lands behind the modal.
   - Step 4 says «reopen with `details`».
   - Fix: reset `pending` in a `finally`, or make `onConfirm` report its outcome; close the dialog, or show the error inside it, for non-conflict codes.
3. **major** `PublishConflictsDialog.tsx:45-52, 87-103` — The dialog ignores `ActivityRingConflict.type` (`"CLASS" | "RING_BLOCK"`, `schema.d.ts:4500`).
   - A `RING_BLOCK` conflict (an existing ring block) counts as fixable by «Anul·la les classes en conflicte». `ready` becomes true, and the row shows «0 inscrits».
   - R-07-05 only lets classes (`cancelClasses`) and training bookings (`cancelBookings`) be forced. Against the api, publishing then answers the same 409, which leads straight into finding 2.
   - The mock hides this: `activity-handlers.ts:315` clears every conflict with `cancelClasses`.
   - Fix: show block conflicts as non-forceable (no checkbox; [PUBLICA I APLICA] disabled, with an explanation) and filter the class checkbox on `type === "CLASS"`.
4. **major** `ActivityPage.tsx:632-635` (`refreshVersion`) — After an image or document upload, the activity (and so the baseline and `version`) is replaced with the server's copy, but `form` keeps the whole old snapshot, not just the user's edits.
   - `changes()` (`:200-265`) then reads every field another admin changed meanwhile as a local edit. [DESA] sends the old values with the fresh `version`, so `STALE_VERSION` never fires.
   - Result: a silent lost update, which defeats the R-07-04 optimistic locking.
   - Fix: rebase only the fields the user has edited, or refresh only `version`/`image`/`documents`.
5. **minor** `ActivityRegistrantsPage.tsx:373-377` — Each row links to `/abonats/{member.id}`, which is ADMIN-only. An INSTRUCTOR who clicks gets a blank `RequireRole` fallback: a dead link (hard rule 3). Render plain text when `readOnly`.
6. **minor** `ActivityPage.tsx:1384` — The plain publish confirm (`<Button onClick={() => void publishWith(...)}>`) has no pending/disabled state, and every attempt gets a fresh `Idempotency-Key`.
   - A double click sends two POSTs, and the second one's `INVALID_STATE` toast replaces «publicada».
   - `publishWith` re-throws `ADMIN_TEXT_REQUIRED` (`:555`), which becomes an unhandled rejection here.
7. **minor** `ActivitiesPage.tsx:348-354` — «Inscripcions» of a `FINISHED` activity without `maxPlaces` reads «obertes · socis». Step 2 limits that text to `PUBLISHED`; `FINISHED` should show «—» (or the count).
