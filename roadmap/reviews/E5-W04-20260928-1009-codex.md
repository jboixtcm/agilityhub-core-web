# Review E5-W04 — minor issues

## Findings

1. **minor** `e2e/core/e5-core.spec.ts:1396` — The cancellation check still uses «Qualsevol», where a cell is free whenever **any** ring is free. It can pass even if the cancelled booking’s ring remains occupied, so it does not prove the slot release required by step 3(e), R-09-10 and T-09-25. Select `training.ringId` and assert that exact slot becomes `FREE`.

2. **minor** `e2e/core/e5-core.spec.ts:1749` — Cleanup is an ordinary test in a serial suite. An earlier failure skips it, including the new branch intended to cancel entries left by failed flows. `afterAll` restores jobs and time but does not cancel created records; those remain until Docker teardown. Move the cancellation logic into a failure-safe cleanup hook, retaining the final-state assertions required by step 3(h).

3. **minor** `e2e/core/e5-core.spec.ts:1234` — The Spanish pass only partially repeats steps (a) and (d), despite step 3(g). It never checks that either new booking appears on 03, that joining removes the class from 04, or that the waiting entry appears on 03. Spanish rendering/navigation regressions can therefore pass. Reuse the corresponding Catalan flow assertions with localized expectations.

4. **minor** `e2e/core/e5-core.spec.ts:109` — The integration spec hand-writes API types (`Booking`, `SeatHold`, `TrainingSummary`, `JobRunAnswer`, etc.), widening enums to `string` and weakening required fields. This violates AGENTS rule 4 and disconnects the contract-adoption tests from generated contract changes. Import generated schemas, using `Pick` where only selected fields are needed.
