# Review E6-W02 — needs changes

## Findings

1. **major** `packages/api-client/src/followup.ts:58` — Idempotency keys survive successful submissions. Creating a text-only task, then intentionally creating another with identical text, reuses the first key and silently replays the first task. A read-only in-memory reproduction produced two successful calls but one server task. Step 3 requires one key **per submission**, not per payload forever. Retain keys for unresolved retries and retire them after success; test both retries and independent identical submissions.

2. **major** `packages/api-client/src/followup.ts:138` — The editable list loads only the default first 50 tasks. Older tasks are accessible solely through `FollowupHistoryDrawer`, which disables editing and supplies no mutation callbacks (`packages/ui/src/tasks-panel.tsx:923`). Consequently, an older pending task cannot be completed, edited or deleted, and an older completed task cannot be reopened. This leaves R-10-10 and the Definition of Done incomplete. Paginate the editable list or provide management actions from history; test with more than 50 tasks.

3. **minor** `apps/clubs-admin/src/instructor/StudentRecordPage.tsx:327` — Opening history unmounts the editor because `Drawer` returns `null` when closed. New-task text, selected files and inline task edits live inside `TasksPanel` and disappear when the user returns. This makes the D13 editor lose drafts during its own history flow. Preserve task drafts above the drawer or keep the editor mounted; add a history round-trip test with unsaved text and files.

4. **minor** `apps/clubs-admin/src/instructor/StudentRecordPage.tsx:127` — Attachment-opening failures have no visible feedback on the main record. `openAttachment()` catches failures into `followup.error`, but D13 displays that error only inside the normally closed editor. The history drawer likewise displays `history.error`, not attachment errors. A failed clip click therefore appears inert, contrary to AGENTS rule 4 and step 3’s catalog-error handling. Render the translated error on the surface containing the clicked attachment and test failed requests.

5. **minor** `apps/clubs/src/history/HistoryPage.tsx:230` — A saved `/historic?tipus=TRAINING` URL remains filtered to training when the club disables `FREE_TRAINING` and `ACTIVITIES`. The API returns no items and `types: ["CLASS"]`; this condition hides every type control, including “Tot”, leaving no way to clear the filter. Reconcile the selected type with the returned catalog, clear unsupported selections from the URL and reload. Cover this R-10-14 / §9 combination.

6. **minor** `packages/api-client/src/uploads.ts:66` — Required client-side attachment validation remains incomplete for instructors. Parameter requests return 403, which becomes an empty limits object; the picker then accepts every size, type and count until the API rejects it. The report acknowledges this dependency, but steps 2–3 explicitly require validation before requesting upload URLs. Resolve an instructor-readable limits contract, or obtain an explicit scope adjustment before treating this requirement as complete.

7. **minor** `apps/clubs-admin/src/instructor/student-record.test.tsx:216` — D13’s T-10-32 coverage renders English only, alongside the Catalan tests; neither this file nor its Playwright spec renders Spanish. The report’s claim of es/en coverage across all three screens exceeds the evidence. Add the required Spanish D13 render and assertions, then update the report.
