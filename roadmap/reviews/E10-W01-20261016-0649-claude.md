# Review E10-W01 — needs changes

## Findings
1. **major** `apps/clubs-admin/src/console/tabs/ParametersTab.tsx:38-56,216` — The Paràmetres tab shows each catalog **default** as the club's current value. `parameterRow` falls back to `definition.default` and `version: 0`. The contract publishes no read of a club's parameters: `PlatformClub` has no `parameters`, and only `GET /platform/parameter-catalog` and `PUT …/parameters/{key}` exist.
   - **Effect:** a platform admin looking at a club that overrides a key sees a wrong value. Any save of that key gets a `409 STALE_VERSION` that can never be resolved, because nothing can read the real version.
   - **Rule:** Step 3 limits the record to «the tabs whose operations the contract publishes». The executor raised this as question 1 but shipped the tab anyway.
   - **Fix:** until the api publishes `GET /platform/clubs/{id}/parameters`, do one of two things. Either hide the tab, or show only the catalog with «valor actual no disponible» and an explicit «sobreescriu» action. A test should assert that a stored override is never shown as the default.
2. **major** `apps/clubs-admin/src/console/NewClubWizard.tsx:98-109` (+ `club-definition.ts:124`) — The wizard's «preset AgilityHub» theme is copied from `useBranding()`, which is the branding of the **host** the console runs on.
   - **Effect:** on a club's admin host the new club inherits that club's colours and typeface. The real-core run did exactly this: it ran on the Cànic admin host, so `core-D19-fitxa-checklist` created a club with Cànic's theme.
   - **Rules:** this leaks one club's branding into another (AGENTS rule 2, white-label). It also skews R-17-06's `branding` item («colors ≠ preset»), which the api computes against its own preset.
   - **Fix:** take the product theme from a product-owned source, such as the `packages/ui` token defaults or a published preset. If `ClubDefinition.theme` accepts `preset` (S17 §3 shows `theme: { preset: null, … }`), send that instead of literal colours. Add a test that renders the wizard under a club branding.
3. **minor** `roadmap/evidence/E10-W01/D19-llista-1280-fosc.png` — The «1280 px» full-page screenshot is 2002 px wide: the document overflows horizontally and the shell stops at 1280.
   - The module chips are also clipped mid-word («Llista», «Enllaç») in the Mòduls column, and every column after it needs horizontal scrolling. That is why a second «llista-columnes» screenshot was needed.
   - **Rule:** AGENTS rule 6 (desktop 1280 layout).
   - **Fix:** wrap or cap the chips (for example the first N plus «+k»), and contain the overflow inside the table.
4. **minor** `apps/clubs-admin/src/console/shared.tsx:301` — `sameValue` compares by `JSON.stringify`, so it is order-sensitive for arrays.
   - `ModulesTab` and `LocalizationTab` rebuild `modules` / `locales` in `CONSOLE_MODULES` / `CLUB_LOCALES` order. If the api returns them in another order, these break:
     - Toggling a module on and off leaves the form dirty.
     - After a successful save, `useRebasedDraft` treats the field as «edited» and keeps the form dirty.
   - **Fix:** compare these fields as sorted sets, or normalise `club.modules` / `club.locales` to catalog order in `themeValues`-style helpers.
5. **minor** `packages/api-client/openapi/openapi.json` (commit `16fde14`) — The staged `openapi.next.json` (`7942586e`) was swapped in and `pending.json` overlays were pruned inside a feature task. AGENTS rule 4 reserves that to the adoption task, and this task's Steps have no step 0.
   - The executor disclosed it. `openapi.next.json` is still present and byte-identical, so the loop will see it as still pending.
   - The organizer should confirm the adoption and clear the staged file.
6. **minor** `scripts/i18n-check.mjs:181` — The exemption `"console:payments.sepa."` covers the whole SEPA subtree, so unused SEPA keys will never be reported. Narrow it to the dynamically built keys only.
7. **minor** `apps/clubs-admin/src/App.tsx:1000-1003` — An account with only the platform role that hits an unknown path renders the console list under that path (e.g. `/foo`), with no redirect. The URL and the «Consola» highlight then disagree, and reload or share behaviour is odd. Fix with `navigate("/consola/clubs", {replace})`.
8. **minor** T-17-12 coverage is partial, as the executor acknowledged:
   - The Dominis tab and its DNS instructions are out (cut #1). With no domains UI, the checklist's `dns` item («Dominis verificats») can never be completed from the console, so every club stays below 7/7. This should be stated in the cut-#1 list or raised with the api.
   - The real-core spec only exercises an account that has a club role (it lands on `/tauler`). The «platform account without a club» entry from S17 §2 is proven only with MSW.
9. **nit** `tabs/ThemeTab.tsx:518-528` — The native `<input type="file">` shows the browser's English «Choose File / No file chosen» (visible in the screenshot). It is not i18n'd (rule 1). Use a labelled button plus a hidden input, as other upload screens do.
10. **nit** `tabs/PaymentsTab.tsx:358,373` — The secret fields use `type="password"` with `autoComplete="off"`, which browsers ignore for passwords. Use `"new-password"` so the browser does not offer to save Stripe secrets as a site credential.
11. **nit** `shared.tsx:340-367` — A failed `onReload()` after a successful write is silent. The tab keeps the old `version`, so the next write returns `STALE_VERSION` with no hint as to why.
