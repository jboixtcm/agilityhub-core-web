# Review E11-W06 — needs changes

## Findings

1. **major** `packages/auth/src/auth-client.ts:199` — The fallback lease does not guarantee mutual exclusion. Two tabs can both read an empty lease, then each write and verify its own owner before starting a refresh. A read-only probe of the extracted implementation reproduced both acquisitions. The lease also expires after 10 seconds without renewal, even while its request remains pending. This leaves W3’s concurrent-refresh/revocation failure possible (S01 R-01-06). Use a concurrency-safe fallback with ownership maintained throughout the request; test separate execution contexts and requests exceeding the lease duration. The current single-event-loop test misses these cases.

2. **major** `apps/clubs/src/App.tsx:1236` — The automatic ADMIN handoff runs whenever 03b observes a remembered ADMIN, including an explicit visit through “change profile.” That immediately sends the user away instead of allowing another choice, contrary to S01 §2/03b and R-01-07. It also runs after `selectProfile("ADMIN")` updates the session, alongside that handler’s own handoff at line 1265. An isolated React probe reproduced **two handoff requests from one click**. Restrict automatic handoff to the post-login landing and share one guarded handoff operation; cover explicit profile switching and assert exactly one request/navigation.

3. **minor** `packages/auth/src/auth-client.ts:1070` — W3’s “three tabs restore with one refresh” requirement remains unimplemented. `tokenGeneration` and `currentTokens` belong to each client instance; another tab’s successful refresh cannot update them. Every waiting tab therefore refreshes again. `auth-client.test.ts:485` explicitly expects three refreshes and three distinct tokens, while the skip test uses a password login in the same client. Share the fresh result between waiting tabs without persisting access tokens, and assert one token request for simultaneous restores.

4. **minor** `packages/auth/src/session.tsx:195` — Automatic session expiry still loses the requested route. The provider sets `signedOut: true` for every `signedOut` event after authentication, including `handleRefreshFailure()`, and this branch deletes the return path and opens plain `/entrar`. A tab on `/reserves/:id` whose refresh expires therefore returns to its landing after login. W1 requires preserving the requested path through authentication. Distinguish deliberate logout from session failure; clear the destination only for deliberate logout and test expiry on a detail route.

5. **minor** `roadmap/tasks/E11-W06.md:98` — The adoption summary contradicts the committed snapshot. `BillingIncidentCode` gains `NO_NEXT_INVOICE_DATE`, not `MANDATE_PENDING` or `NO_PAYMENT_METHOD`. The summary also omits the new `/members/{id}/next-invoice-date` endpoint, required `PeriodRemittance` fields, and `COLLECTION_DATE_PASSED` rollback blocker. Correct the inventory required by “Before step 1” so downstream adoption work uses the actual contract.
