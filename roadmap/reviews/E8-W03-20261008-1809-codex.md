# Review E8-W03 — needs changes

## Findings

1. **major** `packages/ui/src/universal-list.tsx:680` — Changing between operators that use suggested values, such as `eq` → `lt`, permanently disables the value selector and “Add filter.” The handler clears the value and sets loading, but the loading effect does not depend on `filterOperator`; `suggestedValueActive` remains unchanged. Reproduced with the actual component: the loader runs once and the selector remains “Carregant valors.” This breaks step 6 and affects other universal lists. Preserve the selection or reload it when the operator changes; add an `eq` → `lt` regression test.

2. **major** `apps/clubs-admin/src/census/InactivityLeavePage.tsx:478` — Contract-valid array filter values can crash the queue. `Filter.value` permits arrays, but `filterValue()` converts them to `""`. An applied month range with `value: ["2026-10", "2026-12"]` consequently calls `formatMonthTitle("")`, throwing `RangeError: Invalid month`. Saved-view array values are also discarded. Normalize scalar and array values consistently, and test API responses and saved views containing arrays (CONVENCIONS_API §4; step 6).

3. **major** `packages/api-client/src/mocks/member-billing-handlers.ts:718` — Direct leave synchronizes D5 **before** cancelling the pending request and inserting the approved request, without synchronizing afterward. Reproduced for Montse: the response is `APPROVED`, source `ADMIN`, but D5 retains `leaveSource: null` and `hasPendingRequest: true`. This contradicts R-13-10/R-13-17 and the report’s projection-consistency claim. Update the lifecycle documents first, then recompute projections; assert both fields after direct leave.

4. **minor** `packages/api-client/src/mocks/member-billing-handlers.ts:484` — Both queue handlers ignore `q`, although their published contracts specify member-name search and the UI exposes search boxes. A read-only request with `q=NoSuchMemberXYZ` still returned all ten inactivity rows. Apply search before pagination and test matching and nonmatching names (steps 6 and 10).

5. **minor** `packages/api-client/src/mocks/member-billing-handlers.ts:487` — The new sort validation returns invented code `INVALID_SORT`, also at line 654. It is absent from the error catalog and translations; both OpenAPI operations require `400 INVALID_FILTER` for undeclared sort keys. Return the catalogued code and assert it. The green i18n check currently misses this violation of the closed-catalog rule.

6. **minor** `apps/clubs-admin/src/census/MemberInactivityDrawer.tsx:183` — `IDEMPOTENCY_KEY_REUSED {reason: IN_PROGRESS}` displays the message for a key used by another request. The leave, plan and payment drawers use the same code-only mapping. CONVENCIONS_API §7/E80 requires the shared `common:inProgress` message. Use `isInProgress()` before the generic mapping and test the displayed message alongside retained-key retries.

7. **minor** `apps/clubs-admin/src/census/MemberInactivityDrawer.tsx:214` — Fee amounts are divided by a hard-coded `100`; the plan and reactivation price options repeat this. `Money.amountMinor` uses the currency’s minor units, so a JPY amount of 6,000 would display as 60. Reuse the currency-aware formatter in `billing/shared.ts` and cover a currency without two fractional digits (S12 R-12-09/R-12-30).
