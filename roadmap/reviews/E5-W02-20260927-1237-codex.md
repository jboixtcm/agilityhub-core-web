# Review E5-W02 — needs changes

## Findings

1. **major** `apps/clubs/src/training/shared.ts:124` — The module-global offline cache omits tenant, member, impersonation and client identity from its keys. An in-memory probe loaded client A’s summary, unmounted it, then reproduced A’s `eligibleDogs` in client B after a network failure. An in-process identity/client change can therefore reuse another context’s data · S09 §6 tenant isolation / T-09-30 · Scope the cache to the authenticated tenant and subject, invalidate it on identity changes, and add isolation tests.

2. **major** `apps/clubs-admin/src/training/RingBlockCard.tsx:153` — The ADMIN cancellation confirmation disappears after `RING_HAS_BOOKINGS`. Refetch makes the selected slot non-bookable; lines 117–120 silently select another range, changing `placement` and hiding the confirmation. A probe reproduced 17:30 changing to 18:00 with no confirmation button. The existing test clicks before refresh settles. Already-occupied training slots are also excluded from selection · R-09-13 / task step 6 · Preserve the submitted range while confirming, support ADMIN selection of forceable training conflicts, and test after the refreshed grid arrives.

3. **major** `apps/clubs/src/training/shared.ts:247` — Tab eligibility is fetched only when `client` or `enabled` changes. Returning focus does not refresh it, and the training page’s separate reads cannot update it. Newly granted rights leave the tab hidden; revoked rights or a subsequent `MODULE_DISABLED` leave a dead tab visible. A focus-event probe reproduced the stale visibility with no additional request · R-09-01, S09 §7, task steps 2–3 · Share the eligibility query between shell and page and invalidate/refetch it on focus and relevant refusals.

4. **minor** `apps/clubs/src/training/TrainingPage.tsx:523` — A failed selected-day counter request renders an indefinite skeleton. The error branch checks only eligibility and slots, while confirmation remains enabled without a summary. A probe returning `INTERNAL_ERROR` for the counter produced no alert, no retry control and an enabled confirmation · S09 §2 loading/error states / task step 2 · Handle `counter.status === "error"` explicitly and keep confirmation disabled until the required summary is available.

5. **minor** `apps/clubs/src/instructor/RingBlockPage.tsx:96` — The fallback time selectors omit the last morning slot. Filtering boundaries to `< 14:00`, then dropping the last start, leaves 13:00 as the latest start and 13:30 as the latest end. With `FREE_TRAINING` off, a valid 13:30–14:00 block cannot be entered · R-09-11, S09 §9 and §13-12 · Generate selectable intervals by their start time and include their ending boundary; add a boundary test.

6. **minor** `packages/api-client/src/mocks/training-handlers.ts:463` — The mockup-day `/ring-blocks` handler bypasses the normal handler without checking INSTRUCTOR/ADMIN authorization. `mockupBlock` accepts an otherwise valid MEMBER request and creates a block; its ADMIN check applies only when cancelling existing bookings. This makes permission behavior depend on the requested date and weakens the authorization evidence · S09 §6 / T-09-30 / task step 9 · Apply the staff and impersonation guards before mutation and add negative role tests.
