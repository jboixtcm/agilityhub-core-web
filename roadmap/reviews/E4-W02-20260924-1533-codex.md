# Review E4-W02 — needs changes

## Findings

1. **major** `apps/clubs-admin/src/planning/RingBlockDrawer.tsx:420` — Reservation-cancellation confirmation can apply to different bookings than those displayed. After `RING_HAS_BOOKINGS`, changing the ring/date/times leaves the old booking list visible; confirmation sends the **current** fields with `cancelBookings: true`. An in-memory probe reproduced showing ring A’s booking while submitting an override for ring B. `CreateClassDrawer.tsx:456` has the same pattern. This breaks the confirmation required by steps 7–8 / R-06-05 and R-06-11. Clear the confirmation whenever relevant fields change, or freeze the submitted request until confirmation completes; add regression tests.

2. **major** `apps/clubs-admin/src/planning/SelectedClassCard.tsx:343` — Editors remain enabled during PATCH. An administrator can click ACCEPTA, then change another field while awaiting the response. The subsequent reload remounts the card through `CalendarPage.tsx:768` (`id:version`), silently discarding that later edit while showing “Canvis desats”. This undermines R-06-09’s editing flow. Disable editors until the refreshed version is applied, or preserve edits made after the submitted snapshot; test with a delayed response.

3. **minor** `apps/clubs-admin/src/planning/calendar-shared.tsx:96` — Ambiguous local times resolve to the second occurrence instead of the first required by R-06-14. Executing the production helper for `2026-10-25 02:30 Europe/Madrid` returned `2026-10-25T01:30:00Z`; the required first occurrence is `00:30:00Z`. This shifts ring blocks for clubs open during the repeated hour. Implement explicit overlap disambiguation. The reported DST tests exercise a separate fixture helper at 08:30 on surrounding days, so they do not verify this production behavior.

4. **minor** `apps/clubs-admin/src/planning/CreateClassDrawer.tsx:269` — Changing the start time can undo the opening-hours clamp. With Saturday hours 09:00–14:00 and a one-hour duration, selecting the offered start `13:50` sets the end to `14:50`; line 167 then adds that invalid end to the options. The resulting request violates R-06-09’s opening-hours constraint and receives `OUTSIDE_OPENING_HOURS`. Clamp the derived end or restrict starts by duration, and extend the Saturday test to change the start after selecting the date.
